## 1. 上下文缓存复用什么

流程为：**全片采样帧与真实时间 → 视觉编码 → 视频前缀预填充 → 独立问题分支评分**。共享的不只是视觉 encoder 输出，也包括语言模型处理视频前缀后的状态；不需要先生成一份文本背景摘要。

固定核查官方提交 `7f8b38aa7df67721303cdc61f06d8435f3c7db89`：

| 官方实现 | 已确认的功能 | 本项目责任 |
|---|---|---|
| [`timejev/asymmetric_video_memory.py`](https://github.com/MCG-NJU/VideoJev/blob/7f8b38aa7df67721303cdc61f06d8435f3c7db89/timejev/asymmetric_video_memory.py) | `_encode_video_sample` 预填充并保存注意力 KV、卷积/循环状态及时间隐藏状态；提供 `encode_video`、`forward_with_video_memory`、`video_cache` | 接入公开 4B 权重与输入协议，验证时间绑定、缓存身份、命中率及资源开销 |
| [`timejev/timestamp_option_memory.py`](https://github.com/MCG-NJU/VideoJev/blob/7f8b38aa7df67721303cdc61f06d8435f3c7db89/timejev/timestamp_option_memory.py) | `_cached_logits` 从同一前缀分别计算问题后缀，QA 使用选项 softmax | 构造目标时间段、五维问题与选项，保存概率并按冻结规则导出评分 |

`_fork_prefix_cache` 共享不可变的注意力 KV，为分支复制可变的原生 Delta 状态，避免一道题污染下一道题。**不从零实现这套缓存算法。** 但不能把源码存在写成已完成本地接入或已经测得加速。

此前只检查到 [`videojev_hf/modeling_videojev.py`](https://github.com/MCG-NJU/VideoJev/blob/7f8b38aa7df67721303cdc61f06d8435f3c7db89/videojev_hf/modeling_videojev.py) 的视觉特征复用和 `use_cache=False`，不足以判断整个官方仓库的能力。本版修正这一表述，明确选用原生 Cached 路径，而非假设 HF 包装接口加一个开关即可获得相同行为。

缓存成立的前提是视频采样、前缀格式和模型状态一致。容量不足导致淘汰、输入变化或回看新增画面时，应记录重建及新增计算，旧缓存不会自动包含未读入的帧。

## 2. 每个片段怎样评分

对每个目标时间窗，分别提出结果、信息、情绪、动作、感官五个问题。问题明确限定“只评价这一时间段在全片中的贡献”，使用同一视频前缀的独立分支，不串入前一道题的问答历史。

每题使用六个语义等级和一个未知选项。以下是五个维度共用的等级框架，具体问题和证据要求按维度展开：

| 选项 | 含义 |
|---|---|
| 0 | 有足够证据，但没有该维度的明确额外贡献；普通或重复展示可属于此类 |
| 1 | 有微弱线索，但保留价值很低 |
| 2 | 有一定贡献，属于次要内容 |
| 3 | 贡献清楚，值得保留 |
| 4 | 贡献突出，是重要事件或精彩片段 |
| 5 | 核心贡献，是该维度上的关键结果、转折或高潮 |
| U | 采样覆盖或关键证据不足，无法可靠判断；不能等同于 0 |

例如情绪维度：普通礼貌微笑可能是 0–1；与事件有关的清晰反应可能是 2–3；关键结果引发的强烈且归属明确的反应可能是 4–5。强度、事件归属和对观看/理解的贡献应联合判断，不凭表情激烈单独给高分。其他维度沿用设计讨论中的证据约束。允许多个片段同分，不要求每条视频出现 5 分，也不为制造分差强迫使用全部等级。

官方 [`decision_inputs.py`](https://github.com/MCG-NJU/VideoJev/blob/7f8b38aa7df67721303cdc61f06d8435f3c7db89/timejev/decision_inputs.py) 接收可变长度的 `options`，要求至少两项；[`decision_model.py`](https://github.com/MCG-NJU/VideoJev/blob/7f8b38aa7df67721303cdc61f06d8435f3c7db89/timejev/decision_model.py) 在有效选项上计算 softmax。六档加未知在所查输入/输出接口上可表达，无需仅为选项数扩展重新训练评分头；七选项在本任务中的稳定性仍需运行验证。

保留完整 `p0, p1, p2, p3, p4, p5, pU`，以及最大概率选项和目标时间。通过覆盖与未知门槛、且已知选项概率之和大于零后，拟计算：

```text
s = (p1 + 2*p2 + 3*p3 + 4*p4 + 5*p5) / (p0+p1+p2+p3+p4+p5)
# s ∈ [0, 5]，六个已知等级的条件期望
u = pU  # 单独保留未知选项概率；U 不作为数值 6 或 0 加入评分
```

例如，下表两项最大概率选项都是 5，但拟用的排序分数不同。**数值仅用于解释公式，不是实验结果。**

| 示例 | `[p0, p1, p2, p3, p4, p5]` | pU | 连续分数 |
|---|---|---:|---:|
| A | `[0.01, 0.02, 0.07, 0.15, 0.30, 0.40]` | 0.05 | 4.01 |
| B | `[0.02, 0.05, 0.12, 0.21, 0.25, 0.30]` | 0.05 | 3.60 |

本次改变的是模型要判断的语义等级，不是把旧 0–2 分数乘 2.5。新量表用于后续设计，不重新解释旧预测。六档旨在细分价值强弱，但相邻等级尤其 3、4、5 的可靠区分仍待验证；选项概率不是已校准的高光概率，未知概率也不是保证准确的置信度，等级等距仍是适配器假设。后续可在固定输入、模型、五维规则和融合原则下与旧三档做对照，并明确选项文本及计算差异；本次只更新图文与发布，不启动对照实验。

未知门槛及全维未知处理必须提前冻结。例如 `pU=0.99` 时，不能把极少的已知概率重新归一化成一个看似可靠的高分。完整五维分布、目标时间和来源帧应随评分保存。

## 3. 缓存、细化与回看的边界

- **计算量**：`n` 个时间窗仍有 `5n` 道问题，每题七个选项，不是 `35n` 道题。相较旧三档加未知，选项由四项增加至七项，后缀文本和选项计算增加，不能声称成本完全不变。选定的 Cached 路径复用视频前缀，每道题仍需后缀前向、读取缓存和评分；不是一次前向完成全片五维判断。Joint 多题串联是另一个模式，不混入本版条件。参考[论文 §2.1 与附录 A.4](https://arxiv.org/html/2610.18615)。
- **初评分**：从各维完整分布计算有效分数，再按固定规则融合。图中矩阵仅表达结构，不是已有测量；融合规则与未知门槛尚未冻结。
- **候选细化**：综合高分、证据缺口和时间覆盖，细分候选窗口、边界，必要时比较。细化不能凭旧帧提供不存在的动作细节。
- **按需回看**：只有证据缺口明确且预算允许时，才读取源视频新帧；新帧编码与缓存/输入更新后，重新核验受影响的判断。新帧如何接入全片上下文仍待工程验证，不假定官方原生接口已提供自动插帧更新。
- **停止与选片**：证据足够或预算耗尽后进入选片；保留尚未解决的未知。去重、合并并考虑事件覆盖，输出总时长不超过用户预算，新增间隔与上下文也计入时长，最终按时间顺序输出。

图中的 Agent 闭环是后续设计，初版评分验证不自动授权回看、比较或新增模型调用。
