# TVSum V15：17条无效响应、选片差异与下一步修复方案

日期：2026-11-09。范围：固定10条开发视频、50对候选、普通核验 C 与逐项价值核验 V15 的既有100条响应。本轮仅 CPU 审计和助手查看已有像素，不进行模型推理，不修改旧预测或评价。

## 1. 结论先行

**存在两个不同的问题：V15 的判断与引用关系不一致，导致17/50响应无效；同时，合法输出中的价值比较也没有带来额外选片收益。当前低于 C 的0.4236个百分点，不能直接归因于17条无效。**

| 方法 | 合法响应 | 明确A/B偏好 | 接受替换 | 最终Top-5 mAP |
|---|---:|---:|---:|---:|
| 事实记忆 F-local | — | — | 0 | 56.6465 |
| F + 普通核验 C | 50/50 | 30/50 | 5/50 | 59.8750 |
| F + V15 | 33/50 | 17/50 | 3/50 | 59.4514 |

核对全部替换轨迹后发现：

- 对17个 V15 无效的候选对，C 也全部保留基线：11个偏好原候选、3个不足、2个并列、1个不可比。因此，这些候选对的最终选片两组相同。
- V15 的3个替换全部也是 C 的替换；两组最终差别只有 `XkqCExn6_Us__pair02` 和 `__pair04`。这两条 V15 均合法，分别返回 tie 和 incomparable。
- 该视频 C 的 AP 为78.4132，V15 为74.1771；其余9个视频完全相同。该视频差4.2361个百分点，平均到10视频就是0.4236个百分点。
- 两臂共同给出明确A/B的12个候选对，胜负12/12相同。V15 的条件标注一致率44.12%高于 C 的39.33%，来自不同判断覆盖集合，不能据此称其比较能力已经提高。

这批视频已反复用于开发。以上是当前冻结实现的结果归因，不是独立测试集上的泛化结论，也不证明所有弃判都错。

## 2. 17条到底哪里无效

100条原始响应全部用冻结检查器在 CPU 上重放，完全复现 C 的50合法、V15 的33合法与17无效。V15 的50条均通过 JSON/schema 与普通核验公共字段契约；失败发生在新增的跨问题依赖、总体判断与证据绑定检查。

V15 输出为663–943 token，均正常 stop，没有触及1536输出上限。不能把这些失败解释为 token 截断。仍有9处 observation、1处 why、2处 missing 达64字符上限，解释文字的压缩是另一项限制。

## 3. 具体案例：模型问题与契约问题分开看

### 案例A：把“看到了动作”填写成“确认了结果价值”

`GsAD1KT1xo8__pair01`，B为102–104秒，原候选。

- O1：`u`，理由 `Retrieval completion unseen`，即没有看到取回完成。
- O2：`s`，引用 f0160@102.969536，理由 `Specific recovery action`。
- A1/A2又分别支持“伸手接近物体”和“伸入水中”。

这里 O2 应解释“已确认的结果如何解决某个尝试”，模型却重复描述了正在发生的动作。**动作本身可能有价值，但不能因此把结果维度判为成立。** 可将动作证据留在 A 维；结果仍不足。

助手查看旧帧能看到有人俯身水边、另一人拉住其手臂，手中有带状物体；不能单凭这些帧确认是在取回、浸入还是已完成。该案例支持“观察／结果／价值混用”的诊断，不构成对完整事件的人工真值标注。

同类问题还包括轮胎移除过程被填成 O2 的结果价值、警员互动被填成结果、狗跑动被填成完成结果。完整输出保留了原判断，未重写为合法。

### 案例B：同一回答对“信息”的定义前后变化

`i3wAGJaaktw__pair01`，B为22–24秒，原候选。

- I1：`u`，`no diagnostic detail`。
- I2：`s`，f0099@22.989634，`shows gate-closing step`。
- I3：`s`，相对另一段抱住狗的画面，称 `action vs static hold`。

I1原题同时允许“具体答案、诊断细节或关键步骤”。模型在 I1似乎只回答“是否有诊断细节”，到 I2又回答“是否有一个步骤”，没有沿用同一个可观察命题。这是**问题范围与前提引用没有绑定**；不是缺少一个通用的“仔细判断”提示。

旧帧可见金属门位置变化，最后门栅到达关闭位置附近；仍不能由此确认门闩已经锁好。下一版应明确引用同一项事实命题，避免在前后问题之间切换概念。

### 案例C：总体肯定，逐项全部不肯定

`GsAD1KT1xo8__pair04`，A为110–112秒，备选。

总字段 contribution=`supported`，理由是“异常街头互动”；但 O2/I2/E2/A2/S2 全为 `u`。模型同时记录“没有清楚意义或执行细节”。总比较又偏好 B，但 B 的五个第3问也全部不足。

这条同时有总体贡献无支撑和胜负无逐项支撑。当前输出先生成 observation/contribution 等总字段，再生成 q，最后又写 comparison，相当于要求模型多次独立表达同一个判断。**冗余表达使相互矛盾成为可能；生成顺序导致矛盾仍是待验证机制，不能仅凭字段顺序断言因果。**

### 案例D：不是引用了不存在的帧，而是同一依据被写了两套

`kLxoNp-UchI__pair01`：A为0–2秒标题，B为38–40秒狗的画面。

赢家 A 的 I3/O3引用 `[f0001, f0024]`，分别为1.968633秒和38.972267秒；总 comparison 却引用 A=f0001、B=f0025@39.472767。

这些都是合法输入帧，f0024与f0025都在 B 内，相隔0.5秒；但前者狗侧脸无字幕，后者出现字幕。因此不能直接认为不同帧等价，更不能自动改写引用以便通过。模型没有维持同一个比较依据，检查器则要求精确对应。

`__pair03`也类似：I3引用 B的f0014，总比较使用B的f0103，来自同一片段的不同瞬间。**应让最终比较引用已有问题／证据记录的ID，由程序展开具体帧，避免模型重复手填两遍。**

### 案例E：当前负向依赖规则确实过严

`XkqCExn6_Us__pair03`：A为70–72秒跃向栏杆，B为136–138秒整理领带。

B.A1=`s`，“Tie adjustment”；B.A2=`c`，“Routine action”；B.A3=`c`，“Routine vs jump”。冻结检查器却要求任何明确第3问（包括 c）都必须有第2问 s，因此拒绝。

**“已观察到普通动作，因此相对优先级不高”在逻辑上并不要求先认定它有正向突出价值。** 原代码按冻结规则运行正确，但规则定义不合适。修复应区分正向优势与有证据的负向比较，保留对观察、共同标准和双方引用的要求；第2问为 u 时不能顺势推成 c。

这不证明模型对普通程度或相对精彩程度判断正确。它说明该错误不能一概描述为“模型违反正确逻辑”。本例两组都偏好原候选 A，未造成最终选片差异。

## 4. 为什么最终没有超过普通核验

### 4.1 当前 mAP 差异来自两条合法弃判

**第一对：`XkqCExn6_Us__pair02`。** A=78–80秒腾空翻转，B=88–90秒攀墙沿。C选择 A；V15两边都确认动作与观看贡献，A3/S3还都标 s，最后却说“都是不同技巧，没有可辩护优先标准”，返回 tie。

其正向第3问的文字只是 `Aerial flip vs wall ride` 和反过来的 `Wall ride vs aerial flip`：**说出了差别，却没有给出有方向的选择理由。** 冻结问题有的问“哪个观察支持差异”，有的问“哪个时刻更值得选”，同一个 s 混用了“存在差异”和“胜过对方”。在8个合法 tie 中，有4个双方同维第3问均为 s；这是定义含糊的信号，不能全部直接算逻辑错误。

这对标注偏好为A/B/tie=13/4/3，支持 C 的方向，但不等于独立视觉事实真值。助手查看旧帧能确认腾空与攀墙等姿态，未看到模型反复提及的滑板；两组的事件命名都需要谨慎。无法从这些帧推定完整落地成功或绝对技巧难度。

**第二对：`XkqCExn6_Us__pair04`。** A=140–142秒整理领带、戴眼镜，B=4–6秒数字时钟。两组事实识别大致一致；C选择人物动作，V15认为动作与时间信息没有共同优先标准，返回 incomparable。

当前提示本来允许用明确观看标准比较不同事件，但15题更多组织为各自的维度检查，没有稳定完成跨维度取舍。另一方面，这对20人偏好为6/7/7，**没有一致支持人物动作更好**。C的最终 Top-5 AP 更高，不代表本对 V15 的不可比判断已经被证明是语义错误；Top-5 AP与单对重要性偏好不是同一个量。

### 4.2 17条无效降低覆盖，却不是本次 mAP 差的直接来源

C的30个明确A/B中，12个在V15仍为相同明确决定，11个变无效，4个变并列，2个变不可比，1个变不足；V15另从 C 的非明确判断中产生5个明确决定，共17个。

因此技术无效确实损失了11个原本 C 能给出明确偏好的位置，但这些位置在 C 都偏好原候选，最终没有替换。不能用“减少17条无效就能涨0.42个百分点”的说法。

还检查了一个仅用于定位控制路径的 CPU 条件：若只看无效响应的原公共字段、忽略新增问题校验，17条中也仅 `XzYM3PfTM4w__pair04` 满足旧替换条件，其余16条仍保留基线。**这不是修复后的预测，没有放宽正式校验，也未据此重算任何新mAP。** 它进一步表明只放行输出不足以解决选片能力。

### 4.3 更细的字段没有自动产生更可靠的事实与优先级

- 有效990个题目中533个不足；第3问主要缺少“为什么更值得选”的依据。
- 同一动作被反复用于 outcome、information、action、sensory 的正向理由，可能只是对同一观察换词，不是多份独立证据。
- C也进行一般观看贡献判断。本对照不是“无价值”对“有价值”，而是一般判断对详细标准、显式逐题回答、引用和依赖校验的组合变化。
- V15实际输出36999 token，C为16402，约2.26倍；实际总输入也增加。预算上限相同不等于推理负担相同。是否因输出负担降低比较质量仍是待检验假设。
- 助手查看7对缓存画面，发现动作物体描述仍有疑点；这些只用于案例审查，不作为独立人工标注或整体准确率。

## 5. 下一步修复：先统一证据与判断，再测试比较收益

以下为建议，**尚未修改冻结推理代码、尚未授权或启动新实验**。旧100次已完成，不把剩余token或GPU时间转成新请求。

### 第一步：CPU契约修订，先不改价值标准或比较策略

1. **每项事实只定义一次。** 给局部观察一个 evidence/claim ID，记录主体、具体动作或状态、原帧ID/PTS和可观察性。每个第2问明确引用对应第1问的同一命题，防止“没看到结果”变成“动作值得看，所以结果成立”。引用绑定仍不替代视觉真实性验证。
2. **逐题先回答，总体贡献由程序按预先声明的规则汇总。** 有已核验的正向第2问可支持一项贡献；没有正向贡献且存在未决项时保持不足。不要让模型另写一套独立总价值结论。事件是否看清与事件是否值得选仍分开。
3. **最终比较引用既有比较记录ID。** 帧引用从该记录确定性展开，避免 q3 和 comparison 再次手写两套帧号。不得把同片段不同帧自动视为等价。
4. **修订负向依赖。** 正向优势要有可见事实与贡献支持；负向优先级可以依据正面观察到的常规／重复内容，但必须给出相同标准下的双方证据。前提 u 不得降成 c。对冲突的分支标记不可用并保留原因，不能删除题目伪造全合法；依赖该分支的最终判断必须弃权。

先用全部50条历史响应与合成边界输入检查，不仅测试17个失败。历史响应只能作为回归材料，旧 verdict 和 mAP 不修改；同时报告完整响应合法率、可用分支率与最终可决比例，避免通过改统计口径制造成功。

重点回归：O1=u/O2=s；I1范围变化；所有Q2不足但总体supported；Q2=c/Q3=c；同片不同帧；某一维未知不否定另一有证据维；外部引用、空引用、证据缺失、两边相反优先主张。

### 第二步：单独修订“差别”与“优先级”的输出语义

保留五维标准和15题覆盖，但第3问必须指向**固定对手、同一比较标准和明确方向**；把“存在差异”与“该差异足以支持优先选择”分开。单纯写“翻转 vs 攀墙”不算比较优势。

每次比较至少说清：比较哪项观看贡献；A、B各是什么可见事实；该差异支持A、B、相当还是证据不足。异类事件可以在共同标准下比较，但不得默认“动作比静态画面好”“越激烈越重要”。同标准的互相胜出必须显式保留冲突；存在权衡时允许并列、不可比或不足，不强迫胜负。

为了判断修复原因，第一步的结构／契约修订与这一步的比较语义修订应分开记录和验证。不要同时更换模型、采样、事实库、价值记忆、替换门槛或加入回看。

### 第三步：重新获得授权后，做固定50对验证

- 优先先跑结构修订版 V 的全部50对，保留当前 C 与旧V15为冻结对照；复用C属于固定控制复用，不称同期新运行。新V只改上述预先冻结内容，旧模型、局部像素/PTS、事实文本、候选、旧理由、排序和评价不变。
- 每次上下文16384、输出1536、事实1024的上限不变；建议新增50次、零重试、token绝对上限819200。工作进程／GPU生命周期由实施协议在启动前冻结；未冻结前不可执行，不自动动用旧额度。
- 继续沿用每组至少95%完整合法的技术目标，但必须另看无支持胜负、同事实不同说法、有效比较覆盖、全部替换的正负效果及完整10视频的mAP。
- 若结构修订通过且仍无比较收益，再单独授权比较语义版本；不因合法率提高就扩至其余30条，也不为“追平C”按这两个视频定规则。
- 正式泛化评估需要后续未参与开发的视频；本轮不能将反复查看的10条包装成独立测试。

最优先的修复是**证据只定义一次、判断明确依赖它、比较有统一方向**。继续扩写价值描述或单纯增加输出token，目前都没有足够证据作为首选。
