## 1. 结论：上一轮修到了哪一层

上一轮修复侧重输出契约：显式提出被反驳的命题、提供片内引用、拒收部分“没有看到”措辞；它没有实现命题之间的语义排斥验证，也没有独立验证可见事实本身。

提示已经要求同一对象、同一时刻的正向冲突（prompts.py 第 16–17 行）。实际 inspect() 主要检查 claim 字符串精确相等、引用是否合法且属于观察引用集合、反证文字是否命中缺证正则（contract.py 第 120–141 行）。模型自己生成观察、自己声称观察有支持，再用该观察作为反证；这些自述并不是独立证据。

因此，40 项 CPU 测试通过证明的是所实现的契约行为正确，不能证明模型看对画面或推理关系成立。不能仅靠继续补关键词，或新增一个由模型自己填写的 incompatible=true 字段，就宣称问题解决。

## 3. 第一优先修复：让反证有可检查的命题结构

### 3.1 固定被审核的原子命题

将原理由拆成小命题，记录原文跨度、主体、属性或动作、取值、时间范围和量词。例如“男孩跳过购物车并落水”至少分为“男孩跳过车”和“男孩落水”。不能把“购物车落水”偷换成第二个命题的否定。

原文没有“全程／始终／每一帧”时，不得自动添加全称量词；歧义须显式记录。每个 claim_atom 绑定原文 hash 与 span，禁止模型在反驳时改写目标、添加 static 等条件。

小规模诊断可先只依据原理由文字预拆分并审校冻结，不参考帧、GT 或期望判断，不把正确答案写入提示。此时结论仅适用于这种固定命题输入；自动命题解析能力必须另测，不能把手工审校输入当端到端自动能力。

### 3.2 把证据类型和时间范围分开

观察记录标出：单帧可见属性、明确状态变化、事件序列、仅来自旧记忆的说法。帧 ID 和真实 PTS 由程序解析，不接受模型自填一个更长的证据区间。

示例：f0091 的车间只描述该帧；f0012 的道路描述另一个时刻。两者同时属于 2 秒候选，不代表一个能否定另一个。采样帧之间的间隔不算连续覆盖。

### 3.3 控制器审核“是否互斥”，保留模型原建议

模型输出原子命题对应的观察和关系建议；控制器另存 decision、拒收原因和规则版本，不直接沿用模型的 contradicted 标签。

依次检查：

1. **目标一致**：原文跨度、主体、谓词是否对齐；“手伸入轮毂”不能作为“轮胎有裂口”的反命题。
2. **时间一致**：明确区分同一时刻、片段部分、整段命题；局部观察不能反驳片段内存在性命题。
3. **实际互斥**：仅接受已定义的有限关系，例如同一可识别物体在同一语义类别下的互斥取值；不同主体、不同属性、不同时间或未知关系不能作为反证。关系表需审校，不能用模型自填的 true 代替检查。
4. **证据可用**：片内引用、主体一致性和可见性有依据；只有 F 中的叙述不能升级为直接视觉证据。

本轮稀疏帧不开放“整个区间从未发生某事件”的否定通道。显式全称命题可被一个可靠的反例推翻，存在性命题则不能仅靠一个无该事件的画面推翻。

这仍不是语义真值保证：对象识别、主体对齐、属性读数可能被模型填错，控制器也不能从 JSON 证明像素内容。未知关系返回合法的不确定状态，随后仍需视觉审查和适当的正向对照。

### 3.4 不用 invalid 代替语义上的不知道

新版本中，引用越界、格式损坏等机械错误才归为技术 invalid；证据不充分或不互斥应成为可追溯的语义 unknown／部分支持。保留原模型提案与控制器结论两个字段，不静默覆写历史预测。

“原理由未证实”不等于“该片段没有价值”，也不能自动降低原分数。已有独立支持的贡献可继续使用；不得把被拒收的推断当成低价值证据。首轮不修改排序算法、五维价值标准或原 F。

## 4. 后置处理的两个独立问题

### 事实记忆和视觉观察是否互相污染

仅在提示中要求“先观察、再判断”，不构成真正独立或盲化。单次模型调用仍同时看到原理由和 F。

在命题逻辑检查通过后，另做固定帧的观察阶段来源对照：让视觉观察阶段实际不接收旧理由／F，再将冻结观察交给后续审核；如需要第二次调用，须单列调用与 token 成本。这会改变阶段划分和信息流，应作为另一轮模块对照，不能混进本轮并宣称是单变量效果。

### 价值不可比较与视觉缺证混淆

保留组 26 次 insufficient 中 10 次双方观察和贡献都已标为已建立；隐藏组 20 次中也有 10 次。部分输出缺的是共享优先标准，并非画面证据。

后续应分别记录 observation_unknown、comparison_criterion_missing、supported_tie。先维持现有比较规则评估反证修复，再单独检验标准选择；不能靠强制胜负提高覆盖率，也不同时改价值权重来掩盖反证问题。

## 5. 分阶段验证建议

### A. 先做零模型调用的控制逻辑回归

建立三类夹具：本次 6 个反证关系、相应同义改写、正向互斥与明确支持对照。对 Wxt 的“静止”“保持不变”“没有滴落”等同义表达使用相同证据类型，不依赖正则逐条枚举。

有些旧输出缺少新结构字段，不能假装 CPU 能自动读懂全部自由文本。人工／助手标注后的结构化夹具只用于验证控制器逻辑，不能记作新模型预测或实验精度提升。原 100 条响应及原判定保持不变，不重算旧模型成绩。

检查必须同时覆盖：不把共存事实判成冲突、不扩大时间量词、不换主体、不丢弃可靠正向反证、无判断时不报完美精度。合法帧引用但语义错误的负例应进入回归集，弥补上一轮 40 项测试覆盖的局限。

### B. 先跑固定 8 个已知案例，一次新条件

这是**建议、尚未授权**的下一轮开发诊断。复用已冻结 case_review_plan.json 的 8 对，涉及原 10 视频中的 7 条；保持原模型、候选、图片/PTS、F、价值 rubric、温度/seed 及各阶段上限。只测试新的 R_keep_v2，冻结的旧 R_keep 直接作对照，无需再次重跑隐藏组。

新模块包含命题表示、提示/schema 和控制器变化，是模块级修复，不宣称纯提示措辞因果实验；记录新增输入长度、格式和输出负担。原生 processor 上下文检查不通过时先停在 CPU 阶段，不私自加 token、删帧或截断。

建议独立上限：8 次总尝试，故障占同一分母，零重试；总 131072 token，每次仍最多 16384，输出最多 1536，F 最多 1024；一次 TP4 worker，含加载和退出生命周期最多 900 秒，即最多 3600 GPU 秒。使用相同 checkpoint 和环境，四卡不空闲则等待，不自动换模型。精确运行器、启动命令和源码 hash 尚未生成，需实现审查后冻结；本文件不是开跑许可。

验收看具体关系而不是先看分数：已知缺证、共存、主体和时间范围错误不再被控制器接受为反证；粗车辆类别的正向反证仍可保留，明确支持事实不被全部降成未知。0 个反证不能记为精度 100%。若依赖助手参考而没有独立人工复核，结果仍只记开发回归，不确认一般语义准确率。

若固定案例再次出现同类错误，或只靠全部 unknown 达标，停止扩量并保留失败，不自动重试。

### C. 小规模通过后，才补齐原 10 视频的完整 50 对

若版本、输入和控制器冻结后不再变化，可沿用已完成 8 对，再对剩余 42 对做同一新条件；补齐需要另行明确授权，不能从上一轮已用尽的 100 次里借额度。若期间修改方案，原 8 对是旧版本 pilot，不得混成新版本完整结果。

完整评价保留全部 50 对与失败，报告反证类型、已接受反证的语义充分性、可靠支持保留率、不确定率、invalid、决策覆盖及共有决定上的一致性。既有 TVSum 重要性评分只评价高光偏好，不是“是否发生某动作”的事实真值。需要人工语义参考的指标明确标注参考来源与分母。

8 对 pilot 不是完整 10 视频性能，不能报全 50 对收益或新 mAP。即使覆盖率提高，也要检查是否依赖未证实事实。
