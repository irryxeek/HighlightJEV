# TVSum 固定十视频：引用时间与截断修复、三组重跑

## 本轮目标与范围

依据用户“排查并修复引用时间不匹配和输出截断，然后在固定10条TVSum视频上重跑三组对照”的授权执行。使用原 Qwen3.8-27B BF16、原十视频、原像素与真实 PTS、原采样点及 B0 分数。重新生成全部三组结果，旧预测、失败和成本保留。

| 条件 | 输入差别 | 本轮作用 |
| --- | --- | --- |
| D：Direct-HD | 共同视频帧与任务，无文本记忆 | 无记忆对照 |
| F：事实记忆 | D 的输入加事实／事件记忆 | 观察事实记忆的作用 |
| FV：事实＋价值记忆 | 同一事实，加原五类价值证据 | 主比较为 FV−F |

固定视频顺序：`JKpqYvAdIsw`、`JgHubY5Vw3Y`、`sTEELN-vY30`、`Yi4Ij2NM7U4`、`fWutDQy1nnY`、`Bhxk-O1Y7Ho`、`Se3oxnaPsz0`、`cjibtmSLxQ4`、`J0nA4VgnoCo`、`E11zDS9XGzg`。

## 已复现的问题

上一轮 v1.1 已结束，共108次模型尝试：80次建库中79次合法；28次最终判断中仅7次合法，且7次均为 D 的空推荐。另2次 F／FV 因上游记忆无效而未运行。不能将回退 B0 后三个条件均为61.3167解释为价值模块有效。

- **11次最终判断引用时间不匹配。** 例如 `fWutDQy1nnY__select_F` 输出 clip148，即296–298秒，却引用 `f0016` 的148.477秒图像。该例支持“秒数与片段索引混淆”的解释；其他错位不能一概归因于此。
- **7次最终判断截断。** 原512 token上限下，冗长分组、解释或 `missing_evidence` 未结束，JSON不完整。
- **3次其他最终输出契约失败。** 包括重复片段或推荐总数超过5。
- **1次记忆依赖失败。** `Se3oxnaPsz0__mem_g02` 将引用不确定观察的价值标为 supported，不能作为可靠证据继续传播。

以上来自保存的响应与机械检查；不是独立人工语义标注，也未证明模型完全缺少时间理解。

## 修复内容

### 1. 显式绑定片段与来源帧

CPU 按原0.5秒容差，为每个原本有合法来源的2秒片段确定一个来源帧：选择距片段中心最近的原帧，同距时按真实 PTS、帧ID确定。模型选择完整 ID，例如 `c0074_f0016`，不再分别生成 clip编号与来源帧。

十视频逐条证明新候选域等于旧时间检查能够支持的片段域。没有新增帧、扩大容差，也没有按 GT 或旧预测选择候选。CPU 解引用结果明确标为绑定来源；**这保证时间邻近与索引一致，不能保证画面语义真实。**

### 2. 精简输出并增加完整回答空间

最终输出改为最多5个平铺 `picks`，含绑定ID、排序层级、至多2个事实引用和至多100字符理由；`missing_evidence` 至多120字符。允许同分和空推荐。三组统一将输出上限由512提高至1536 token，建库仍为1024。

使用已安装 xgrammar 支持的固定格式单行 JSON，禁止任意缩进与空白；实际默认分隔符保留一个空格。保留原始响应和终止原因，发生截断仍计为无效，不补写部分 JSON。

### 3. 将原记忆依赖契约前移到生成阶段

为0–3条事实及明确／不确定组合建立15种输出布局。supported 价值只能引用确实存在的明确事实；unknown 保留不确定性。原记忆接受规则、事实装箱及分数导出函数保持不变，不把历史失败改判为成功。
