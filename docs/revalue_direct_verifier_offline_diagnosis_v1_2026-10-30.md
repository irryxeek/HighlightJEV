## 1. 主要结论与证据等级

**已经核验的事实**：原 verifier 已完成 139 次尝试、14 个 worker；81 个输出通过契约，58 个 invalid。旧评价 precision/recall/正确区间误报率为 53.70%/34.12%/46.30%，未通过门槛。139 条旧响应的 CPU 契约重放与原成功解析或首次失败逐条一致。

**新增可审计发现**：

1. 39 个“query 直接证据必须全在片内”的失败中，32 个是空引用，只有 7 个涉及片外或混合区域。不是 39 个片外证据问题。11 个“缺失或重复事实引用”细分为 9 个缺失、2 个重复。
2. verifier 与固定时长规则共同报警仅 8 条。verifier 独有 46 条中有 24 个 IoU 代理错误和 22 个代理误报；时长规则独有 32 条中有 26 个代理错误和 6 个代理误报。当前没有“verifier 已优于简单规则”的证据。
3. 固定案例中发现片内帧被说成片外、边界方向与理由相反、关键 query 条件被弱化等问题。部分输出虽然引用合法，判断理由仍不成立。
4. 价值字段不是缺 key，而是大量被标成“不适用”：合法输出中 361/405 为 `not_applicable`，`unknown=0`。现有案例支持“适用性解释过窄、NA 与证据不足混淆”的疑点；没有受控提示词对照，不能确认提示不足是根因。

**不能据此宣称**：所有 invalid 都是视觉识别错误；所有低 IoU 都是真正错事件；GT 存在多少错误；改提示词一定提升；五类价值已经产生独立收益。图像审阅由助手完成，独立人工语义核验仍为 0。

表中是既有评价，非本轮重新评价。invalid 和 insufficient 继续保留在召回分母中，不能当成支持或正确输出。

### 3.1 58 个首次契约失败

| 冻结校验的首个失败 | 数量 | 离线细分与解释 |
|---|---:|---|
| query 明确判断没有纯片内证据 | 39 | 32 空引用；5 after+inside；1 before+inside；1 after-only |
| 缺失/重复事实 ID | 11 | 9 引用不存在的事实；2 重复引用同一事实 |
| query 引文不是原文子串 | 2 | qid 9491 合并了双空格；qid 5361 把原文 `ta yellow cloth` 改成 `a yellow cloth` |
| 单条事实混合片内和上下文帧 | 1 | qid 3939，e6 同时包含 before 与 inside |
| end=supported 无片内证据 | 1 | 状态与必需引用不匹配 |
| end=too_early 无 after 证据 | 2 | 缺少该方向的片外继续证据 |
| start=too_late 无 before 证据 | 2 | 缺少该方向的片外继续证据 |

这里是**首次失败**，不保证一条输出只有一个问题。失效链可在原响应 → facts → frames → PTS/region → frozen validator 中复查。32 空引用与 7 片外引用的细分沿用已有解释并作全量契约核验；新增缺失/重复 ID 的细分和逐例时间来源核查。

39 个 invalid 的 facts=[]，另 19 个 invalid 有事实；3 个合法输出也允许 facts=[]（在 unknown/NA 等情况下）。因此“空 facts”本身不是错误定义；无证据却作 supported/contradicted 或明确边界判断才会违反相应契约。

qid 9491 的空白归一化仅用于说明失败触发点，不回写 query/预测、不放宽旧契约、不重算合法率。词法问题可以与语义问题同时存在，修空格不等于修好整条响应。

### 3.2 合法引用仍遗漏的检查

冻结代码检查 ID 是否存在、引用是否重复、来源区域是否满足规则；它没有验证事实文字是否真实，也没有理解理由中的时间关系。例如 too_early/too_late 引用了 inside，不能自动证明所引用的画面是“片内冗余”。

`missing_evidence` 只保存问题，不会自动让 query=supported 降为 unknown；值字段也不直接进入最终拒绝公式。qid 9572 就同时给出 query=supported 和“手机内容是否为文章尚未确认”。这说明当前可执行契约与语义要求之间仍有空隙，不是本轮可以通过改失败输出解决的事。

额外文字审计发现：87 条理由提到了结构化 evidence 未绑定的帧，1 条提到未选为本次输入的帧 ID，90 条至少一个 reason 达到 schema 的 180 字符上限。这些是语法线索，**不是 87/1/90 个已确认视觉错误**。例如模型可能描述已看到但未写入事实链的帧。全部响应 finish_reason=stop，也不等于每句理由完整；180 字符约束可以限制句子长度，但尚无证据证明它导致当前误报。

## 6. 价值字段为何大量 NA：回应最新讨论

### 6.1 看到的是“不适用”，不是字段丢失或已测得的低检出率

五个 key 都受 schema 要求。81 条合法输出共 405 个值字段：361 NA（89.14%）、42 supported、2 contradicted、0 unknown；61/81 条五项全 NA。没有独立价值标签，因此这些比例不是价值检测的召回率。58 条 invalid 未混入合法价值分布；其原始字段仅可用于案例诊断。

| 维度 | supported | contradicted | unknown | not_applicable |
|---|---:|---:|---:|---:|
| outcome 结果 | 1 | 1 | 0 | 79 |
| information 信息 | 10 | 0 | 0 | 71 |
| emotion 情感 | 2 | 0 | 0 | 79 |
| action 动作 | 15 | 1 | 0 | 65 |
| sensory 感官 | 14 | 0 | 0 | 67 |

### 6.2 实际给模型的解释确实较短

冻结 contract.py（本地资料：`$ZEROSHOT_ARTIFACT_ROOT/revalue_direct_verifier_v1_1_2026-10-30/source_snapshot/contract.py:68`） 对五类分别只给括号短释：完成/状态变化、理解事件的可见细节、反应及归属、动作阶段/质量、外观/构图。运行提示未包含方案文档中“进球要区分射门尝试”等具体核查示例；JSON 示例五项都填 `not_applicable`。

提示同时强调目的相关、不要强制适用、普通事件不因不精彩而错误。这些限制符合 grounding 主线，但缺少对各状态的逐项操作定义。schema 对 supported/contradicted 要求事实引用，NA/unknown 可以空引用；它没有机械验证“NA 的理由是否真的说明无关”。

这些都是实现事实。**“默认示例诱导 NA”“多字段任务负担过大”“解释过短造成漏检”仍是机制假设**，当前单臂输出不能确认因果。

### 6.3 固定案例表明适用性解释存在问题

- **qid 9572，横屏手机上的文章**：information=NA，理由是“不需要看手机之外的细节”；但 missing_evidence 又问内容是否为文章。文章/视频之分对 query 明确相关，尚未核实应保留不确定性，不能用“不适用”绕开。
- **qid 5466，剪辑软件展示制作过程**：information=NA，模型只核查“软件存在”，同时承认是否展示制作过程仍缺证据。需要区分识别界面与验证请求中的过程。
- **qid 7435，拿橙色蛇**：action=NA 的理由是“动作可见且匹配”，sensory 则引用橙蛇与绿衣判 supported。这是适用性解释不一致的支持案例；整条响应仍 invalid，不能当合法效果样本。
- **qid 4008，分享早餐**：把“看不到相关动作/信息”作为 action/information=NA 的理由，提示没有把“任务不要求”和“任务要求但证据不足”分清。

### 6.4 讨论层面的判断，不是新实验协议

补充提示引导有依据，重点应是把维度落到 query 的具体可核查条件，而不是增加抽象介绍或强制五项非空。例如结果核查“是否完成请求中的结果”，信息核查“关键内容能否辨认”，动作核查“是否发生所要求动作”。与任务无关才 NA；任务相关但画面无法确认应 unknown；有可引用支持或反证才进入对应状态。

普通“男子说话”不必有强情绪，emotion=NA 可以正确。不能为提高非 NA 比例制造情绪或精彩程度要求；当前主线仍是 grounding。现有 CPU 最终状态也不直接使用 values，所以“填出更多价值字段”不等于更准确筛出反例，更不等于定位提升。

本轮只明确这些问题和解释边界，没有改提示、改状态定义、设计新模型条件或运行对照。若未来要判断提示引导的实际收益，需要新的独立授权与可比较证据。
