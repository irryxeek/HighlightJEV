## 1. 已核实的问题

旧 v2.2 共 278 次响应：220 条合法、58 条无效。下表左列按验证器遇到的第一个错误互斥计数；右列检查完整原始响应，允许一条响应存在多类问题，不能相加。

| 问题 | 首个失败原因 | 原始响应中涉及的条数，可重叠 |
|---|---:|---:|
| 同一事实重复引用帧 ID | 25 | 25 |

前三类合计涉及 **56 条不同响应**，其中 10 条存在多类问题。旧提示词已经要求遵守依赖和引用规则，但原生成约束没有完整落实这些规则。当前 XGrammar 0.1.27 的 CPU 探针确认：仅添加 `uniqueItems` 不会阻止重复元素；仅用 `if/then` 也不能可靠约束前提关系。

这是可以复现的输出契约问题。它不等于已经确认模型在视频语义上判断错误，也不能推断修复后 56 条都会转为正确报警。

## 2. 修复内容

### 2.1 在生成时禁止重复引用

对每个事实的 `frames`、每个检查的 `evidence`，使用后端实际支持的有限数组枚举及共享 `$defs`，仅允许不重复的合法 ID 集合。容量保持最多 8 条事实、每事实最多 4 帧。

- `frames` 按输入帧顺序序列化，`evidence` 按事实编号递增序列化；所有允许大小的集合仍可选。
- `ordered_evidence` 保留两个方向的排列，因为其顺序表达 query 中的动作先后，不能按编号排序。
- 引用数组采用紧凑 JSON，例如 `["e1","e2"]`。这是固定后端对数组枚举的格式要求；没有更换输出字段或事实含义。
- 不同事实仍可引用同一帧；不同条件仍可引用同一事实。禁止的是**单个列表中的重复 ID**。

### 2.2 先判断前提，再判断依赖条件

根据冻结的 `depends_on`，稳定地按前提先后顺序输出 checks，保留原 requirement ID、问题文本和 AND/OR/NOT 逻辑。44/278 条输入确实存在原列表中前提排在子条件之后的情况，因此排序变化已记录。

生成分支使用前提的实际状态：所有前提均为 supported 时，子条件可选择 supported、contradicted 或 unknown；任一前提为 unknown/contradicted 时，子条件只能选择 unknown。仍允许根条件 contradicted、全部 unknown 和零事实。**不通过事后提升前提状态来让子条件合法。**

只枚举被其他条件依赖的节点是否 supported；当前输入最多两个这种节点、四个有效分支，避免枚举大量完整回答。前提先输出也避免“先给出子条件结论，再由结构约束迫使尚未输出的前提变成 supported”。

### 2.3 保持严格验收，不修写旧回答

`validate_contract`、`validation_schema`、`validate_output`、逻辑聚合及指标函数与 v2.2 的 AST 相同。旧 220 条合法响应得到完全相同的解析结果，旧 58 条无效响应仍以完全相同的首个错误失败。

没有做事后去重、改状态、放宽验证器或重算指标。Q 和 Q+V 使用同一生成约束和公共说明，Q+V 仍只增加原有价值提示；未改变价值定义。

## 5. 尚未解决与科学边界

1. **真实视觉证据是否正确**：格式合法仍可能包含幻觉、人物/事件误绑定或重复事实文本。
2. **时序证据**：原两条缺少有序事实的问题未在本轮扩展处理；PTS 顺序、两个锚点、ordered 引用是否属于 evidence，仍由旧 CPU 验证器严格检查。
3. **证据不足**：缺音频、采样不足或前提本身不可确认仍会导致 unknown。依赖约束可能增加 insufficient，不能把合法率变化当作检出率提高。
4. **科学收益**：尚无新模型结果，不能声称降低真实无效率、提高 recall 或改善 grounding。新增序列化顺序、格式和提示长度可能影响输出分布，应作为结构约束修复整体记录。
