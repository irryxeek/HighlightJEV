# 01_cover

这次把进展更新到十一月三日。主线仍然是 grounding：希望验证 Direct 找出的区间是否包含 query 所要求的内容，后续再处理时间边界。当前最明确的成果是输出合法性改善，八 B 的二百七十八次判断中有二百七十三次通过契约检查，合法率百分之九十八点二。但检错召回依然很低，价值引导还没有稳定收益。

与上一版不同，三十二 B 已经完成了原清单前二十条、七十四次判断。它没有改善当前验证效果，反而大量停留在证据不足。下面会先说明方法与文献来源，再看完整八 B 结果、同样本模型对照和具体问题。这里不会把更大模型的这次负结果推广成所有任务上的能力结论。

# 02_pipeline

当前主线是 grounding，也就是找到 query 描述内容在视频中的时间区间。REZE Direct 接收整条视频和 query，一次输出区间列表。固定的一百条 query 中，九十八条有合法的非空候选，共一百三十九个区间。

verifier 接收冻结的 query 条件和候选旧帧，在同一次调用中生成可见事实、证据引用和逐条件判断，最后经程序验收，给出支持、报警或证据不足。Q 和 Q 加 V 共享候选帧及真实时间戳。query 条件是助手仅依据 query 编写并冻结的，尚无独立人工审校。这一阶段没有把证据不足接到定向回看，也没有边界检查、区间修正或重新排序。所有定位输出保持原样，当前不能称为完整 Agent 已提升定位精度。

# 03_baseline

我们冻结 REZE Direct，是为了后续实验有统一参照，并不是因为它在所有指标上都优于原来的 Direct。两者在相同的一百条开发样本上，R1 在零点五阈值下是四十二对三十九，在零点七下是二十八对三十，MR mAP 是二十四点七二对二十六点四八。指标有升有降。

两条路径的帧数、提示和输出形式同时变化，所以这不是单变量比较。一百条来自 QVHighlights train 开发池，也不是独立测试集。后面的 verifier 只审查冻结候选，不改区间、顺序或分数。因此后面所有检错数都不应直接翻译成这张表里的定位指标提高。

# 04_literature_to_design

当前价值判断设计主要借鉴四个工作。VisionReward 把多维偏好拆成具体视觉判断题，我们借鉴的是问题化思路，为五类视角写出支持证据、反证限制、缺证标准和不能做的推断。UnifiedReward-Flex 会按输入细化评价条件，我们借鉴任务适用性，只启用 query 真正需要的视角。与原论文的动态评价不同，我们在看到候选结果前冻结要求，避免为了某个片段临时加标准。

DSG 用原子问题和依赖关系减少矛盾回答，我们据此显式记录对象、属性和动作关系，并增加帧引用、时间作用域和 unknown。VTune 研究定位后的事件及组成条件验证，提醒我们：能够输出区间，不代表模型能可靠确认区间内容。因此我们在 Direct 后加 verifier，同时单独衡量 verifier 自己是否可信。

组合后就是：先拆 query 条件，再生成适用核查题，模型输出事实与帧引用，最后给三值判断。五类名称沿用我们此前的 ReVALUE 方案，不是复制某一篇论文的维度。当前也没有使用这些工作的训练权重、奖励分数或 VTune 训练；Q 与 Q 加 V 对照测的是这一套价值提示的额外贡献，收益仍待验证。举例说，横屏手机能提供外观证据，但不能自动证明屏幕是文章；看不清应当保留未知。

原始文献链接：[VisionReward](https://arxiv.org/html/2412.21059v2#S2)、[UnifiedReward-Flex](https://arxiv.org/html/2602.02380v1#S3.SS2)、[DSG 官方项目](https://google.github.io/dsg/)、[On the Consistency of Video Large Language Models in Temporal Comprehension / VTune](https://arxiv.org/html/2411.12951v1)。本项目迁移依据见二〇二六年十月三十一日的相关工作调研与价值判断设计 v2，本次重新核对原始来源，未复现论文性能。

# 05_ablation_design

Q 组根据 query 条件检查人物、物体、动作和关系。Q 加 V 使用完全相同的条件，额外提供结果、信息、情绪、动作和感官五类适用视角的判据：什么可以支持、什么是反证、什么仍然缺证，以及哪些推断不成立。

两组固定候选、帧像素与时间戳、模型、query 条件、schema 和验收。每组一百三十九次，一共二百七十八次，零重试。五维视图由条件映射得到，不是另外让模型打五个分再加权。某个维度不适用，只表示这个 query 没有对应要求；不能直接称为漏检。条件由助手仅看 query 构建，尚未经过独立人工审校。价值块带来的提示长度和注意力变化也一起发生，所以测的是整个提示包，而不是抽象价值概念的纯因果效果。

# 06_main_results

八 B 的完整一百条结果保持不变。按一百三十九个候选计算，其中八十五个与任一 GT 的最大 IoU 低于零点五，作为错误代理，另外五十四个是代理正确。Q 检出六个、误报一个；Q 加 V 检出八个、误报两个。召回从百分之七点零六到九点四一，精确率从百分之八十五点七一到八十。

所以这里说的是净增加两个正确报警和一个误报，不代表两组报警集合有包含关系。报警数量少，且低 IoU 可能来自边界或标注口径，并不必然是内容错误。我们还没有独立人工语义标签，两组也都没有通过原来的探索性门槛。当前能说提示引导改变了部分判断，还不能说它稳定提高了价值判断或定位精度。

# 07_contract_repair

工程修复的效果比科学收益更明确。同一个验收口径下，旧 v2.2 有二十三条无效，新 v2.4 有五条。公共修改包括事实和帧绑定、依赖检查、生成顺序以及普通重复引用去重，因此不能把全部变化归因到某一项。

还要把生成和验收分开看：本轮原始严格验收有五十二条无效，普通重复引用去重恢复了四十七条，最终剩五条。去重只是删掉完全重复的普通引用 ID，不删事实描述、不改语义状态。未定义引用、重复事实定义及时间顺序证据仍严格检查。剩余两条达到输出长度上限，JSON 不完整；三条声称确定的时间关系，却没有足够有序事实。合法率提高是工程成果，不表示事实已经正确。

# 08_verdict_distribution

每组一百三十九个候选按支持、证据不足、报警和无效完整分解。Q 分别是七十、五十九、七、三；Q 加 V 是六十三、六十四、十、二。证据不足比例分别为百分之四十二点四五和四十六点零四。当前没有补证闭环，所以这些未知还没有通过新的视觉证据得到解决。

支持也不代表定位成功。Q 的七十个支持中有四十一个低 IoU，Q 加 V 的六十三个支持中有三十二个低 IoU。它们需要进一步区分是内容漏检、区间过长还是标注差异，不能直接全部标成语义错误。我们需要审查判断是否有证据支持，而不是只追求减少 unknown 或增加支持数量。

# 09_matched_32b_results

三十二 B 这轮已完成原清单前二十条、三十七个候选，两臂七十四次判断，六十六条合法。两模型只比较同样的二十条；这一子集中有二十五个低 IoU 代理错误、十二个代理正确。

八 B 的 Q 与 Q 加 V 分别检出两个和四个，三十二 B 分别检出一个和零个，召回是百分之八、十六、四和零。三十二 B 两组都没有支持判断，累计六十五次证据不足、八次无效。Q 加 V 没有报警，精确率未定义；不能把零误报解释为更好。八 B 虽然产生更多确定判断，但同子集的支持中仍有低 IoU，也不等于语义准确。

这一批是原清单顺序前缀，未按 GT 或效果筛选，不能代表完整一百条。候选、帧、提示和 schema 相同，但三十二 B 用三卡流水线并行、CPU offload 和不同的上下文、prefill 配置；这不是只改变参数规模的严格因果对照。实际七十四次消耗三十五万八千零三十四 token，三卡累计三万五千三百七十二点零二二 GPU 秒，约九点八三 GPU 小时。它是累计卡时，不是墙钟等待时间，也不包含更早版本的启动失败成本。

# 10_fact_generation_case

用户在前端看到三十二 B 描述很空泛，我们核对了原始记录。QID 二七八一、Q 组的三十七到四十一秒候选，在两模型使用同一批十六帧时，三十二 B 只写“所需证据不可得”，引用的还是四十四点七四五秒的片后帧，三个条件均为未知。本条正常结束、只输出三百七十八 token，既不是截断，也不是前端或去重把文字删掉。

八 B 在相同输入上写了人物投掷和黄色烟雾相关的两条描述，引用片内三十七点二三七、三十九点七四零秒。模型进一步声称击中目标，但助手查看单帧无法独立确认完整因果。并且这个候选的 IoU 是零，GT 在五十六到六十、七十二到九十八秒，所以描述具体或模型支持都不等于定位正确。

整个七十四次中，三十二 B 有二十五条非空事实仅由三种固定套话组成，八 B 为零。统计精确匹配 visible fact、The required evidence is not available 和 The required evidence is not established，包含无效输出中可解析的字段，不是事实准确率。CPU 契约探针复现了传播机制：没有片内事实时，schema 只允许后续条件为 unknown。但为什么模型首先选了空泛事实和片外引用，仍然未知。示例措辞、结构约束或运行配置是需要分别检验的假设，尚不能认定根因。

# 11_semantic_binding_case

这个保留案例说明，引用存在并不代表足以支持结论。query 要求男子横持手机阅读文章，候选是二十八到三十七秒。模型描述可读文字和带字幕的视频，随后用这些描述去支持“文章”条件。

疑点是证据到结论是否发生语义跳跃。可读文字或字幕不自动等价于文章，但文章也可能嵌入视频，所以仅凭响应文字不能断言区间一定错误。这是助手审阅模型响应发现的支持关系疑点，不是独立人工视觉标签。下一步需要看事实是否真的支持必要条件，不能只查引用编号存在。

---

# 12_dependency_case

另一个问题是模型可能扩大条件依赖。query 要求女子在盆栽旁独白，候选是零到一百五十秒。独白因为没有音频，被判未知。问题在“植物是否在盆里”这一条件：冻结合同写明没有前置依赖，模型却说它依赖独白，因此也给未知；同时自己的事实多次描述了盆栽。

这里可以确认的是响应内部不一致，不能据此独立确认画面。后续可把单项可见事实和整体 query 分开处理，让程序按冻结依赖传播，而不是让模型自行添加依赖。这仍是待验证的修改建议，当前不能写成已经解决。

---

# 13_semantics_and_boundaries

内容与时间覆盖是两个问题。图中的关系只是概念示意，没有真实时间比例。一个很长的预测区间可能确实包含目标事件，但大量无关时段会让它的 IoU 很低；只核查语义的 verifier 可能支持它，却没有验证定位边界。

同一百三十九个候选上，冻结 CPU 时长规则召回百分之三十六点四七、精确率七十七点五、误报九个。它比 Q 和 Q 加 V 更容易发现过长区间，同时误报更多。这是已有规则的评价，没有调阈值。这个对照提示必须拆开内容错误和边界错误。当前原区间不变，尚没有新的 R1 或 MR mAP 提升。

为了把这些问题落到实际样本，现在前端可以并排播放同一 query 的数据集 GT 标注区间和原始 Direct 预测。可以逐段切换，播放到区间结束自动暂停，并对应查看 Q 或 Q 加 V 的事实、必要条件、引用帧和原始回答。这张图是已完成页面的真实截图。

八 B 完整一百条的服务在服务器端口八七六六，三十二 B 前二十条在八七六五，通过 SSH 转发后可在本地浏览器打开。两套页面共用八 B 的 Direct 基线，三十二 B 只替换后面的 verifier。播放用已有原视频，没有改写预测或生成新模型输出。GT 是数据集标注参照，并不替代独立语义审查；目前独立人工语义标签仍为零。这个工程结果是让后续审查更方便，不算模型性能提升。

# 15_next_steps

下一步建议先利用视频页面做独立审查，按固定规则覆盖支持、报警、证据不足和无效，区分内容错误、边界错误、可见性不足和标注疑点，同时审校 query 条件及依赖。

随后固定旧帧和 query，先单独检验占位示例文字，再用独立条件检查 schema 约束；三卡运行路径作为另一项因素，不同时改动。验收要看事实是否具体、来源是否正确、条件判断是否合理，不能只看 JSON 合法或 unknown 变少。

事实质量可用以后，再比较 Q 和 Q 加 V 对同候选的改善与退步。只有确认确实缺少视觉信息的案例，才进入等量均匀补帧与定向补证对照；时间边界另设分支。如最终改写区间，再评价 R1 和 MR mAP。所有这些是待讨论建议，本次只更新汇报，没有运行新实验；也不要求模型为了好看的结果强行给确定判断。
