# 32B 与 8B 事实生成差异：离线核查

## 范围与结论

针对前端截图核查 `qv_2781_w02__Q`，并统计原固定前20条query的全部74个Q/QV请求。只读取已有输入、原始回答与账本；新增实验调用、GPU分配、源视频采样均为0。统计是生成文本与状态描述，不是人工语义准确率或新的grounding评价。

这条32B回答缺少具体可见事实，属于真实保存的生成内容问题，不是前端或引用去重丢失描述。尚不能确定退化由提示、结构化解码、模型自身还是推理配置导致。

## 已核验的事实

- 两图均为QID 2781、候选 `[37,41)` 秒、Q组。两边完整输入对象相等：16张相同像素/PTS的旧帧、query、提示、任务契约、schema及prompt token IDs相同。
- 32B原文只定义一个事实：`The required evidence is not available.`，绑定片后`f0089`（44.744701秒）；原文重复该帧4次。去重只将重复ID变为1个，事实文字不变。三个条件均unknown。
- 8B定义两条具体事实，引用片内`f0074`（37.237202秒）和`f0079`（39.739700秒）。助手查看原像素可见室内人物投掷姿态及黄色烟雾；单帧不能独立证明“回旋镖击中目标”的完整因果过程。8B对多人条件的理由也存在宽松解释，不能直接当作真值。
- 本条32B正常stop，输出378 token，低于2048上限；输入3712 token。不是本条输出被截断或上下文空间不足。
- 两边BF16；32B使用三卡pipeline parallel、较小prefill块和CPU offload，8B为单卡，执行条件并非完全相同。仅输入一致不足以排除运行配置影响。

## 可复现的控制机制

输出schema将片内事实放在片外事实之前。当仅生成片外事实、片内事实数量为0时，checks分支只允许unknown。本例先输出片后帧引用，随后无法形成确定性判断。该机制解释退化如何向条件核查传播，但不证明它为何首先选择片外帧。

普通CPU schema检查验证：原对象允许；仅替换事实文字仍允许；片外唯一引用对应的r1改成supported不允许；同一合成对象仅把引用换为片内f0074则允许。合成对象仅用于契约检查，不是模型预测，不代表相应语义成立。

当前验收能检查ID、区域、依赖等结构，却不能判断`facts.text`是否确实描述可观察事实，因此“缺少证据”这种元判断可以通过验收。结构合法不等于事实质量合格。

## 假设与待验证事项

提示示例含`visible fact`和默认unknown理由；32B多条输出复用了这些文字，支持“示例文字影响生成”的假设。强schema将事实选择和后续判断绑定，可能放大早期选择偏差。这些都尚未通过模型干预对照证明，不能直接写成根因。

后续应优先拆分事实提取与判断退化：分别检查提示示例与结构化约束的影响；一次只改变一项，保持帧和query固定。三卡运行路径也尚未被独立排除。本轮未修改提示、验收规则或实验源码，未启动任何新模型分支。
