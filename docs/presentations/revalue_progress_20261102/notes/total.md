# 01_cover

这次汇报覆盖十月三十日至十一月二日的 grounding 基线和 verifier 对照，数据快照截至十一月二日晚上十一点五十六分。阶段结论是：输出更可靠了，但检错能力仍然不足，价值引导的稳定收益尚未确立。最新八十亿参数模型对照完成了二百七十八次调用，归一化后有二百七十三条合法输出，合法率为百分之九十八点二。三百二十亿参数模型完成了权重和输入准备，但首次启动失败，还没有正式请求和预测结果。

这里需要同时保留两种判断：工程上，引用和契约问题已经明显减少；科学上，能否稳定找出定位反例，仍缺少充分证据。后面会先介绍固定基线和对照设计，再用结果及案例说明剩余问题。

---

# 02_pipeline

当前主线是 grounding，也就是找到 query 描述内容在视频中的时间区间。前面的 REZE Direct 接收整条视频和 query，一次输出区间列表。固定的一百条 query 中，九十八条有合法区间，共得到一百三十九个候选。

verifier 接收冻结的 query 条件和候选帧，从可见事实、证据引用推进到条件判断，最终给出支持、报警或证据不足。Q 和 Q 加 V 两组共享帧及真实时间戳。这个阶段完成的是局部内容验证，尚未把证据不足接到定向回看，也没有执行边界检查、区间修正或重新排序。原始定位区间和分数保持冻结，因此当前结果不能表述为完整 Agent 已经提升了 grounding 性能。

---

# 03_baseline

我们把 REZE Direct 固定为后续参照，但它相对旧的自定义 Direct 并没有一致优势。完整一百条开发样本上，零点五阈值的首区间召回由百分之四十二变为三十九，零点七阈值由百分之二十八变为三十，区间平均精度由二十四点七二变为二十六点四八。

这说明更换 Direct 路径带来的变化有升有降。两种实现的帧数、提示和输出形式同时变化，不能把差异归因于单一因素。这里使用的是 QVHighlights 的训练集开发样本，也不是独立测试结果。后续 verifier 使用 REZE Direct 的冻结预测，便于比较各验证条件；它没有改写这些定位输出。这里的 Direct 是整视频直接输出时间区间，并非 REZE 的局部窗口密集判断路径。

# 04_ablation_design

这次对照主要考察价值指导是否有助于条件验证。Q 组从 query 拆出人物、物体、动作和关系，检查必要条件是否有证据支持。Q 加 V 组沿用相同条件，在适用时加入结果、信息、情绪、动作和感官五类判断指导。

两组固定了候选、缓存帧和时间戳、八十亿参数模型、query 条件、输出结构和验收规则。一百三十九个区间各跑两组，共二百七十八次调用，零重试。价值维度的适用性由冻结条件映射确定，不能把“不适用”理解成模型漏检；这也不是模型重新生成价值标签。条件本身由助手仅依据 query 构建，尚无独立人工审校，所以后面讨论依赖错误时，还需要检查条件合同和模型执行两层。

# 05_main_results

主要结果是，加入价值指导后，多检出两个低 IoU 候选，同时净增加一个误报。每组完整分母都是一百三十九个候选，其中八十五个与任一标注的最大 IoU 小于零点五，用作错误代理，另外五十四个为代理正确区间。Q 组正确报警六个、误报一个，精确率为百分之八十五点七一，错误召回为百分之七点零六。Q 加 V 组正确报警八个、误报两个，精确率为百分之八十，召回为百分之九点四一。

虽然召回增加了二点三五个百分点，但实际报警数量很少，两组均未通过原探索性门槛。更关键的是，低 IoU 可能来自边界、事件覆盖或者标注差异，不能直接当作语义错误。尚无独立人工语义标签，因此目前只能说出现少量新增检出，不能确认价值引导稳定有效。

# 06_contract_repair

工程修复已经得到验证，但要把不同来源的改善讲清楚。旧版响应按同一套新版验收规则复核，仍有二十三条无效；新一轮只有五条。这里同时涉及事实与帧绑定、依赖检查、生成顺序和普通重复引用去重，所以不是某一项修复的单变量收益。

对新一轮单独审计，严格不去重时有五十二条原始响应不合法；稳定去重恢复四十七条，最终剩五条。这说明合法率提升包含验收归一化的贡献，不能全部解释为模型学会了正确引用。剩余失败中，两条达到输出长度上限而导致 JSON 不完整，三条声称确定时间顺序，却没有提供两个有序事实。未定义引用、重复事实定义和时间证据仍严格检查，原响应全部保留。输出格式更可靠，是目前最明确的工程成果。

# 07_verdict_distribution

结果分布说明，证据不足仍是主要问题。Q 组有七十个支持、五十九个证据不足、七个报警和三个无效；Q 加 V 组分别是六十三、六十四、十和二。每条堆叠柱都保留完整一百三十九个候选，不能只报告有效响应中的比例。

证据不足占比分别为百分之四十二点四五和四十六点零四，加入价值指导后还增加了五个。当前没有补证回路，所以这些样本停留在未知状态。另一方面，支持结论中仍有大量低 IoU 候选，分别是七十个中的四十一个、六十三个中的三十二个。这些需要审查，但不能全部称为语义漏检。unknown 也不能直接转成错误；只有经过核验才知道哪些是可见事实遗漏，哪些确实缺少证据，哪些属于边界或标注问题。

# 08_semantic_binding_case

第一个案例说明，引用存在并不代表它能支持结论。query 要求男子横持手机阅读文章，候选区间是二十八到三十七秒。模型描述了可读文字和带字幕的视频，随后用这些描述去支持“文章”条件。

这里的疑点是证据到结论是否存在语义跳跃。可读文字或视频字幕，并不能自动等价于文章；但文章也可能嵌有视频，因此不能只凭文字响应断言这个区间一定错误。当前证据只支持提出“支持关系存疑”，不能替代对原画面的独立语义核验。这个案例来自助手对既有响应的审查，页面没有把模型描述当作已确认视觉事实。下一步需要检查事实对条件的蕴含关系，而不仅检查事实编号是否引用正确。

# 09_dependency_case

第二个案例更明确地暴露了响应内部的依赖不一致。query 要求女子在盆栽旁独白，候选是零到一百五十秒。独白条件因为没有音频，被模型判为未知，这个判断本身有证据限制。问题出在另一个条件：植物是否在盆里。冻结合同中，这个条件没有前置依赖，模型却说它依赖独白条件，于是也输出未知。

同时，模型自己的事实描述又多次提到盆栽。因此这里可以确认的是响应内部执行了合同之外的依赖传播，尚不能据此证明画面内容。一个后续修复思路是把单项可见事实和整体 query 是否成立分开，让程序按冻结合同传播依赖，而不是让模型自行扩大依赖。这个方向还没有实施验证，不能写成已解决问题。

---

# 10_semantics_and_boundaries

grounding 需要同时关注内容是否出现，以及预测区间是否准确覆盖。上面的示意没有真实时间比例，只解释一个关系：过长区间可能确实包含目标事件，但因为夹杂很多无关时段而低 IoU。仅做内容验证，未必能发现这种错误。

已有冻结时长规则提供了一个对照：同一批候选中，它正确报警三十一个、误报九个，召回为百分之三十六点四七，精确率为百分之七十七点五。它比 Q 和 Q 加 V 更容易捕捉过长区间，但误报也更多，不能代替语义检验。这里引用的是已有评价，没有调整规则阈值。我们需要分别验证内容和时间边界；如果后续真正修正了区间，再报告 R1 和区间平均精度。当前 verifier 没有改写区间，尚未证明最终定位指标提升。

# 11_32b_runtime

更强基模对照目前只有准备和首次启动记录，还没有预测结果。Qwen 三百二十亿参数版本的十四个权重分片已校验，运行器通过一百四十五项 CPU 检查，二百七十八个请求的候选、像素、提示和输出结构也完成一致性核对。但这些准备不能保证显存启动成功。

十一月二日晚上十点五十九分，首次使用零、二、三号卡启动后遇到两类问题。调度器的进程归属检查拒绝清理，随后停止派发，具体触发机制仍未定位。vLLM 也记录显存准入失败：要求空闲二十二点三四 GiB，实际为二十二点三一 GiB，未达到零点九五的准入要求。这不等于加载权重后的 OOM，也不能证明三卡一定跑不动。

这一轮启动了一个 worker，正式请求为零，token 为零，未重试。账本中的四千五百 GPU 秒是保守预留，实际完整生命周期未知。十一点五十六分的巡检没有发现已知进程或进程组残留，历史未确认收据仍保留，没有生成三百二十亿参数模型的评价，不能进行能力比较。

# 12_next_steps

下一步先排查三百二十亿参数模型的运行阻断，对必要变更审查和版本化，保留首次失败记录。科研上的三个验证对象也要分清。第一，审校 query 条件和依赖，并建立覆盖报警、支持、证据不足和无效输出的独立语义审查，避免只挑成功案例。第二，设计等量补证对照，比较旧帧、等量均匀新帧和等量定向新帧，固定模型和核验问题，判断补证本身有没有作用。第三，单独验证时间边界；真正改写区间后，再评价最终 grounding 指标。

这三项任务分别回答：现在的结论是否可信，缺失证据能否补足，时间定位是否准确。现阶段最明确的成果是工程可靠性提高；价值指导、定向回看和边界修正的收益仍需实验。以上是后续建议，新增实验先冻结范围和预算，并保留全部旧预测和失败。汇报希望对齐的原则是，把合法性、语义检错和定位质量分别验证。
