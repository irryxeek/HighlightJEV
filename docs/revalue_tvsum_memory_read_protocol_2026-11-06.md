# TVSum 原40视频：仅改变事实读取策略

## Material Passport

- ARS experiment-agent，run + validate；2026-11-06，memory_read_v1。
- 用户授权：“按这个思路先改进记忆读取策略，复用已有事实库，固定模型、输入帧和token预算，在原40条TVSum视频上做对照测试。”
- 固定原new40完整清单与顺序；属于已查看的开发集。新F-read对比旧F，D为无记忆参照；旧FV仅背景列。

## 唯一干预

保持原每非空时间组首事实及最早uncertain保底。只改变剩余事实的读取顺序：在能完整放入1024原生token的条目中，按以下新增覆盖量的字典序选取：

1. 尚未覆盖的原B0 Top-5候选局部证据；逐个真实PTS落入2秒格±0.5秒。
2. 尚未覆盖的候选之前/之后最近观察点。它们只是时间上下文，不声称同事件或因果。
3. 尚未覆盖的event_family短标签。
4. 尚未覆盖的源帧ID数量。
5. 更接近原候选中心的真实观察点；完全并列时按事实ID。

每选入一条后更新覆盖，直到无完整条目能放入。最终按原bank顺序渲染，不重写事实、不重新排序呈现、不读取value字段/GT/旧成绩、不添加语义关键词规则或模型检索。

## 固定项与解释边界

- 同Qwen3.8-27B revision、BF16、TP=4、同环境和引擎参数；同旧图片及顺序、PTS、choice表、提示其余部分；温度0、seed0。
- F最大1024 token，输出1536，上下文32768，均沿用旧上限。实际输入长度允许变化并报告，不用填充制造等长。
- schema结构不变，只随active事实变化替换可引用ID枚举。这与事实视图变化不可分离。
- 原B0候选本来已在提示中，本策略会增加候选锚定；不代表已解决全片语义检索或相对高光价值。
- 完整40视频都运行一次新选片；即使新旧F完全相同也保留，不按变化、成绩或合法状态选子集。
- 不重建库，不改V，不回看，不修改旧预测，不启动其他分支。

## 执行与停止

- 新轮最多40次选片尝试、零重试、一次四卡worker启动。全部调用独立计账，不使用旧额度。
- 精确总token预留在CPU完成原生token化后冻结，等于40份提示token数+40×1536，且不超过1,310,720。
- worker运行超时3600秒，清理余量60秒，四卡生命周期记录上限14,640 GPU秒；仅使用空闲卡并在加载前复核。该运维上限用于本轮，非扩展其他实验的授权。
- CPU契约失败不加载模型；运行时故障停止且不重试；格式/引用无效保留原响应并继续剩余清单。禁止按中途指标停止。
- 完整40分母；无效/未尝试/弃权沿用旧B0回退，分别报告，不伪造新预测。结束后确认所属进程退出，再进行CPU评价。
