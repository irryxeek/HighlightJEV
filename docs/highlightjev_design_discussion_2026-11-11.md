## 2. 建议的流水线

```mermaid
flowchart LR
    V[整片采样帧和真实时间] --> C[复用官方 Cached 视频前缀]
    C --> Q[时间片段与维度问题]
    Q --> M[选项概率转为五维连续分数与未知概率]
    M --> S[固定融合规则和候选排序]
    S --> B[时长预算与重复控制]
    B --> O[合并相邻片段并按时间输出]
```

“整片”指采样覆盖整个时间轴；上下文长度上限不保证局部细节可见。第一版优先沿用现有 3 秒候选窗口和源帧时间，以便复用 REZE 的评价导出；若减少采样，必须记录每个窗口实际被观察的帧，不能将未采到关键动作误归因于评分失败。

共享视频表示不是此前的事实/决策文本记忆库。第一版不需要先生成 caption 或建图，也不自动增加回看。记忆可在以后用于压缩过长上下文或跨任务复用。

## 3. VideoJev 提供的能力与边界

论文将时间候选与文本答案选项统一为直接评分，提出共享视频前缀的 Cached 和 Joint 推理。它为这条路线提供的是共享上下文和结构化判断接口，未报告通用高光五维评分与预算摘要实验。[论文 §2.1](https://arxiv.org/html/2610.18615)

本轮核查公开实现提交 `7f8b38aa7df67721303cdc61f06d8435f3c7db89`：

| 接口 | 实际输出 | 对本项目的意义 |
|---|---|---|
| `task=grounding` | 同一 query 对整条时间轴候选的 sigmoid 分数 | 5 个维度 query 可得到完整的候选×五维矩阵，不必逐片段重复提出同一个维度问题 |
| `task=choice` | 该问题各文本选项的 softmax 概率 | 将某个片段某一维的 0–5 六个等级与证据不足写成七个选项，读取完整分布 |

这两种接口都需要验证任务迁移。grounding 分数表示与查询事件的匹配/归属，不能直接叫“价值强度”；choice 的原生能力是选择答案，加入有序价值选项不代表已经训练成可靠的高光量表。

**11 月 12 日源码复核修正：官方已有语言模型前缀缓存。** 初稿只检查 Hugging Face 包装入口，范围不足，不能由该入口的 `use_cache=False` 推断整个官方仓库不支持 Cached。

| 官方路径 | 已核实的行为 | 本项目采用方式 |
|---|---|---|
| `timejev/asymmetric_video_memory.py` | `_encode_video_sample` 预填充视频前缀，保存注意力 KV、卷积/循环状态及时间隐藏状态；`encode_video`、`forward_with_video_memory`、`video_cache` 提供复用与管理 | 接入已有机制，按视频建立与校验缓存身份 |
| `timejev/timestamp_option_memory.py` | `_cached_logits` 对每道题从同一视频前缀分支，只运行问题后缀；QA 输出选项 softmax | 目标时间窗与维度问题使用独立分支，不继承上一题的问答历史 |
| `videojev_hf/modeling_videojev.py` | `encode_video` 复用视觉特征，`predict_features` 的语言前向使用 `use_cache=False` | 该便捷包装入口不能替代前两项的原生 Cached 执行路径 |

官方 `_fork_prefix_cache` 共享不可变的注意力 KV，并为分支复制可变的原生 Delta 状态；它并非每道题从零重算视频前缀，也不是将所有缓存整份复制。上述为固定提交的静态源码核验，**尚未完成本项目对公开 4B 权重、输入格式和执行器的联调**，不能写成已经测得缓存加速。[原生缓存实现](https://github.com/MCG-NJU/VideoJev/blob/7f8b38aa7df67721303cdc61f06d8435f3c7db89/timejev/asymmetric_video_memory.py)、[独立问题评分](https://github.com/MCG-NJU/VideoJev/blob/7f8b38aa7df67721303cdc61f06d8435f3c7db89/timejev/timestamp_option_memory.py)、[HF 包装入口](https://github.com/MCG-NJU/VideoJev/blob/7f8b38aa7df67721303cdc61f06d8435f3c7db89/videojev_hf/modeling_videojev.py)

首版选用 **Cached 独立问题模式**：固定视频前缀先计算一次，每题仍要处理问题与选项、读取前缀并计算分数。记录视觉编码、预填充、缓存命中/淘汰、问题后缀次数、显存和耗时；缓存被淘汰或输入改变时不得假称只计算过一次。Joint 将多题串在同一序列，后题可看到前题的问题与选项，是另一个条件，不与 Cached 混称。[论文 §2.1 与附录 A.4](https://arxiv.org/html/2610.18615)

时间分数原生对应两帧一组，而非固定 2 秒或 3 秒；需保存真实时间边界，按重叠时长映射到统一评价网格。第一版高光输出使用原始分数曲线，不使用默认“单个连续区间”解码替代高光选择。

## 4. 两种实现应分开命名与验证

### 4.1 HJ-G：少量维度 query，给全时间轴打分

每视频固定 5 个维度 query。每个 query 指向一种具体价值证据，模型对所有原生时间候选输出分数，得到 `P[时间候选, 维度]`。

优点是直接利用现有 grounding 接口，问题数少；局限是抽象价值词可能只得到主题相关性。应问可核查的事件特征，而不是只写“精彩”“有信息”“有情绪”。它适合作为轻量参照，输出称为“价值线索匹配分数”，不伪装成已校准的高光概率。

### 4.2 HJ-O：片段×维度的 0–5 六档＋未知判断

这是与用户设想最一致的实现。问题显式绑定目标时间，例如：

> 结合整片视频，只评价 24–27 秒。该片段的情绪反应是否与主线事件有关，并对理解或观看这个事件有实际贡献？在 0–5 六个等级和“证据不足”共七种描述中，选证据最支持的一项。

统一等级框架如下，各维度用本节及第 5 节的具体证据约束展开：

| 选项 | 贡献等级 |
|---|---|
| 0 | 有足够证据，但没有该维度的明确额外贡献；普通或重复展示可属于此类 |
| 1 | 有微弱线索，但保留价值很低 |
| 2 | 有一定贡献，属于次要内容 |
| 3 | 贡献清楚，值得保留 |
| 4 | 贡献突出，是重要事件或精彩片段 |
| 5 | 核心贡献，是该维度上的关键结果、转折或高潮 |
| U | 目标片段未被充分采样，或关键证据不足，无法可靠判断；不等于 0 |

情绪维度示例：普通礼貌微笑可能是 0–1；与事件有关的清晰反应可能是 2–3；关键结果引发的强烈且归属明确的反应可能是 4–5。不能仅凭强度给高分，必须核查事件归属与贡献。允许同分，不要求每条视频出现 5 分或覆盖所有等级。

读取 `p0,p1,p2,p3,p4,p5,pU`，同时保存最大概率选项、完整分布和目标时间。通过覆盖与未知门槛且分母大于零后，拟计算：

```text
s = (p1 + 2*p2 + 3*p3 + 4*p4 + 5*p5) / (p0+p1+p2+p3+p4+p5)
u = pU
```

`s` 是 0–5 范围内的连续分数；未知既不作为 0，也不作为数值 6 进入期望。必须同时报告 `pU`；未知占优时不允许将极少的已知概率归一化成一个看似可靠的高分。未知门槛和全维未知处理需在正式协议中冻结，不根据 AP 调整。图稿说明提供了可复核的数值示例，均不是实验结果。

官方输入检查接收至少两个选项的可变长度列表，评分输出对有效选项做 softmax，所查接口支持表达七项。增加选项不要求仅为输出类别数重新训练模型，但不能据此认定模型已经学会可靠地区分六档高光价值。[选项输入](https://github.com/MCG-NJU/VideoJev/blob/7f8b38aa7df67721303cdc61f06d8435f3c7db89/timejev/decision_inputs.py)、[评分输出](https://github.com/MCG-NJU/VideoJev/blob/7f8b38aa7df67721303cdc61f06d8435f3c7db89/timejev/decision_model.py)

本次改变的是语义等级，不是把旧 0–2 结果乘 2.5。选项概率不等于校准后的高光概率，六档等距是适配器假设；模型仍可能同分、饱和或混淆 3、4、5。后续可固定视频、帧、时间窗、维度规则与融合原则，对照 **0–2 三档＋未知**与 **0–5 六档＋未知**，记录选项长度及计算差异。该对照尚未冻结或执行；增加等级不能自动修复主题偏见、幻觉或不可靠的价值标准。

若沿用旧 val10 的全部 1,260 个窗口，五维仍共 **6,300 个判断问题，每题七个选项**。按选定的官方 Cached 独立问题路径，每视频复用一次前缀，仍有 6,300 个问题后缀计算；不是仅 50 个问题，也不是一次前向输出所有片段五维分数。相较旧三档加未知，选项从四项增加至七项，后缀文本与选项计算增加，不能声称成本完全不变。另加每窗口一个通用高光问题的对照，需要再计 1,260 个。这个规模说明必须先核查容量和实际计算复用，不能直接套上一版实验预算。

VideoJev 的评分头不直接生成事实、解释或证据句子。第一版可审计轨迹应保存源帧/时间、完整问题与选项、各选项概率、分组与缓存记录。额外解释生成需另列调用，不能把后生成的解释当成评分时真实使用的证据。

## 5. 五维问题怎样具体化

沿用现有五维定义，核心条件是对全片事件的贡献，不把主题匹配当价值：

| 维度 | 对目标片段提出的问题 | 已知易错点 |
|---|---|---|
| outcome：结果/进展 | 是否呈现关键完成、转折或明显的前后变化？ | 不能从尝试直接推断成功 |
| information：信息 | 是否提供此前没有、且对理解主线有用的可验证信息？ | 品牌、场景、主体身份的反复展示不自动加分 |
| emotion：情绪 | 反应是否清楚、与事件有关，并具有值得保留的强度或意义？ | 微笑不等于高潮；反应归属不明应保留未知 |
| action：动作 | 是否出现关键动作阶段、显著难度或能区分候选的执行变化？ | 普通运动和镜头移动不自动加分 |
| sensory：感官呈现 | 是否有与事件有关、值得保留的视觉呈现或揭示？ | 清晰、鲜艳、显眼不等于重要 |

首版固定 query 模板，只替换时间，不让另一个模型为每片段自由生成不同难度的标准。视频特定 query 生成可以后续加入，但那会新增模型调用及适配变量。

评分在全片背景下进行，有机会区分“主体普通展示”和“真正体现状态变化的行动”。这是机制假设；全片上下文也可能加重主题偏见，必须用同骨干的局部/全片对照验证。

## 6. 融合分数与预算选片

先保留完整五维向量，避免只存一个不可解释的总分。任一维度可以支持高光，不要求五维都高。

首版建议用固定的“最强有效贡献”作为简单融合基线：对证据足够的维度取 `max(w_d * s_d)`，无用户偏好时权重固定相同。该规则会放大某一维的误报，不能预称最佳；等权均值可作为事先登记的离线敏感性对照，不在 10 条开发视频上搜索最有利权重。grounding 的各维概率未必可比较，HJ-G 尤其需要报告逐维饱和和融合敏感性。

若引入“总体观看价值”问题，应作为通用评分对照或另一个明确条件，而不是暗中替换五维融合输出。所有维度未知的候选必须标记；正式协议需明确是退出候选、弃判还是使用另一个已预算的基线，不能默默用旧 REZE 分数填回。

预算选片不只是取前 K 名。应依次处理时间重叠、同一事件重复、相邻片段合并，再在总时长约束内选择并按时间顺序输出。

- 默认预算是**输出总时长不超过 5 / 10 / 60 秒**，不是必须硬凑到该秒数。
- 5 秒偏重单个关键瞬间；60 秒需要考虑不同事件覆盖和必要前因后果。可先用固定评分＋预算选择，之后再研究预算条件化评分。
- 扩展上下文、补齐动作前后或连接中间空隙增加的时长必须计入预算。
- 初版使用确定性的时间重叠控制与预算选择；不为了达成恰好 5 秒而未记录地截断关键动作。
- 单纯时间去重不能保证语义不重复。语义去重、事件完整性与边界细化应作为后续独立模块及消融。

**UMT Top-5 mAP 的 Top-5 是五个 2 秒评价单元，不是 5 秒摘要。** 只有得到完整时间评分曲线后，才按原协议评估 Top-5/15/50 mAP；预算输出另报实际时长、人工重要性均值、正例覆盖与冗余情况，不能将两类指标混用。

## 7. 如何保留可解释的最小对照

建议不把全片上下文、五维拆解、新模型与预算算法一次性合并比较。

| 阶段 | 条件与固定项 | 能支持的结论 |
|---|---|---|
| A：接口与覆盖核查 | 无 GT 选定小清单；检查真实时间、每片段帧覆盖、选项概率、分组、未知及成本 | 接口能否表达任务；不是性能结论 |
| B：整片上下文 | 同模型、同一通用目标、同一局部目标帧，对比局部输入与全片输入 | 额外全片视觉证据是否改善判断；如缩小局部帧或分辨率则不能称纯上下文对照 |
| C：五维分解 | 固定同一整片输入，对比通用目标与五维 query；冻结融合规则 | 分维度判断是否比整体判断有效；调用/问题数差异需报告 |
| D：预算输出 | 复用同一冻结评分曲线，对比简单按分取片与预算/去重选择 | 选片器的贡献，不新增模型推理 |

HJ-G 与 HJ-O 的评分含义、问题数量、输出空间不同，应作为独立实现分支报告。建议以 HJ-O 作为用户所提出的“逐片段价值评分”主原型，先做无 GT 选择的小规模接口检查；HJ-G 作为轻量参照。接口检查通过不代表价值判断有效，不能按 GT 挑选有利片段给 HJ-O 评分后冒充全量性能。

现有 TVSum val10 可以继续用于开发，REZE 与最新五维版结果可作为外部参考。新模型和旧模型的差值不能只归功于评分头；全 50 条也已参与开发，最终泛化结论需要另行设计验证。

## 8. 模型选择与尚未解决的事项

复用官方 VideoJev-4B 可免去本项目重新训练，再验证高光任务迁移；其已训练评分头不能直接移到 Qwen3-VL-8B。如果优先保留 Qwen 8B，可先用相同的片段×维度选项读取 token 概率，但应称借鉴 VideoJev 的 Qwen 原型，不能声称已采用其原生学习头或获得同等效率。[官方模型说明](https://github.com/MCG-NJU/VideoJev/blob/7f8b38aa7df67721303cdc61f06d8435f3c7db89/README.md)

当前设计明确采用官方 Cached 路径，仍需验证公开 4B 权重与原生执行器兼容性、缓存身份和真实时间绑定。尚未冻结：实际帧清单与分辨率、HJ-G/HJ-O 首轮范围、全部 query/选项全文、未知门槛、融合与选片参数、适配器源码，以及请求/token/GPU/worker 上限。本次修订不启动实验；缓存复用不代表免计问题后缀、回看新帧或缓存重建的成本。

这条路线的潜在贡献是**全片语境下可核查的高光价值判断，以及随时长预算变化的事件选择**。是否具有方法贡献，需要证明它优于同输入同骨干的通用高光评分，而不只是将已有接口更名。
