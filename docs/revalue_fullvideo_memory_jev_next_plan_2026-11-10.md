## 3. 三个研究问题

1. **记忆增益**：同一模型、相同原始视频帧和任务下，附加结构化记忆，是否改善候选召回与高光选择？
2. **压缩与视觉锚点**：只读文本记忆能否保持质量？给同一份记忆补少量代表帧，是否恢复文字遗漏的证据？
3. **评分接口**：训练过的时间候选评分头，能否提供比生成式打分更有用的排序信号？其输出能否用于高光检测，需要单独验证。

QVHighlights 的 query grounding 与 TVSum 的通用高光检测分开报告。前者衡量是否定位到请求事件，后者衡量观看重要性；不把相关性概率、判断置信度和高光价值当成同一量。

## 4. 基线选择与文献依据

### 4.1 Qwen Direct：本轮内部配对对照

优先沿用 Qwen3-VL-8B-Instruct BF16，记忆构建与最终判断用相同权重、处理器和版本。新名称用 `D_full`，避免与已有依赖 REZE 的 D 混淆。“整片输入”指冻结采样覆盖完整时间轴，不代表逐帧读取全部原视频。

### 4.2 MemDreamer：借鉴消融思路，暂不列为可直接执行的复现

MemDreamer 先建纯文本层级图记忆，再由文本 Agent 检索；论文分别比较记忆结构和检索策略。我们应先隔离表示，再研究检索，不直接把层级图、工具和五维评分一起加入。论文建库使用 Gemini，不能将其收益直接归因于我们同一个 Qwen 8B 的记忆能力；“文本＋代表帧”是本项目新增对照，不是论文原有消融。[论文](https://arxiv.org/html/2606.07512)

本轮检查[项目页](https://aim-uofa.github.io/MemDreamer/)所指向的代码仓库返回 404，暂不能确认可取得实现。本文不声称完成 MemDreamer 复现。

### 4.3 LensWalk：建议的外部 Agent 对照

选择公开的 LensWalk 推理实现：它可规划广域扫描、连续局部观察、跨区间拼接观察，并保留带时间的证据；planner 和 observer 可接同一个本地模型服务。已有代码不等于已在本机运行通过。固定代码提交 `c3cdf13a6ffc6b1ce21af3a0c7813178d17fac77`，默认分支为 `release`。[官方代码](https://github.com/likanchuan09171/LensWalk/tree/c3cdf13a6ffc6b1ce21af3a0c7813178d17fac77)

接入需修改任务读取、终止输出及评价，将 QA 输出改为时间候选，并排除推理输入中的答案/标签。第一版所有观察限制在同一冻结帧池，统计每个 observer 子调用；`scan_observer` 的内部并发不能只算一次请求。该条件命名为 **LensWalk-adapted**。允许重新采样原视频的原生工具版本属于另一个系统实验，不能与静态记忆消融混为一谈。

## 5. 首轮：TVSum val10 的四组最小对照

### 5.1 固定范围与输入

使用已接触过的旧 UMT val10，完整保留以下顺序，不按 AP、失败类型或新预测筛选：

`J0nA4VgnoCo`, `cjibtmSLxQ4`, `JgHubY5Vw3Y`, `Bhxk-O1Y7Ho`, `sTEELN-vY30`, `Yi4Ij2NM7U4`, `E11zDS9XGzg`, `Se3oxnaPsz0`, `JKpqYvAdIsw`, `fWutDQy1nnY`。

这是开发性机制实验，不是独立测试集。后续需要未参与方案调节的评估材料，不能把此前已反复查看的后 40 条重新称为未见测试。

拟从已有帧缓存按时间均匀选取最多 256 个唯一源帧，覆盖全片；若缓存不足则使用全部，禁止重复凑帧。选择只依据时间，记录请求时间、真实 PTS、源帧 ID、像素哈希及变换。每帧像素上限拟为 256×256 等面积，保持比例。统一采样和分辨率必须先经 CPU 上下文预检，再冻结；若不适配，整套方案统一修订，不能运行中为某组单独降配。

候选全集是全片完整 2 秒网格，不预筛 REZE Top-5。所有组使用同一已冻结的通用高光任务文本；标签、历史分数、人工标题、语音和人工失败说明不进入输入。

### 5.2 四组及其能回答的问题

| 条件 | 最终判断读取内容 | 主要对照意义 |
|---|---|---|
| D_full | 全部冻结帧＋真实时间 | 独立整片 Direct |
| D_full+M | 同一全部帧＋同一文本记忆 | 与 D_full 比：在相同原始视觉证据上附加记忆是否有效 |
| M_text | 仅文本记忆，保留来源时间/帧 ID | 与 D_full 比：用文字替代视觉输入后的质量与成本变化 |
| M_text+R | 同一文本记忆＋固定 16 张代表帧 | 与 M_text 比：视觉锚点的额外作用 |

代表帧从同一帧池按 16 个等时段中心确定性选择，不按价值评分、GT 或事后结果选帧。若模型以后自主挑代表帧，应作为新的选择机制消融。

`D_full+M` 输入更长且有额外建库计算，不能声称总成本完全一致；`M_text` 改变了输入模态，也不能单独证明“纯记忆机制”的因果增益。四组采用共同资源上限，另报告实际成本，做质量—成本比较，不用空调用把成本凑平。

首轮只能判断这套记忆流水线是否值得继续研究，尚不能排除额外建库计算本身的贡献。若要形成“记忆结构优于增加计算”的论文结论，还需增加相同总 token/GPU 上限的 Direct 自检查或普通分段摘要对照。不能仅匹配最终判断的一次调用，就称端到端预算已经匹配。

### 5.3 记忆内容与构建

每视频按时间分为 8 组帧，各做一次观察；再用一次文本汇总形成全片记忆，共 9 次建库调用。所有记忆条件共享这份产物及其哈希，不分别重建。

每个事件至少包含：`event_id`、时间范围、源帧 ID、可见事实、与前后事件关系、事件阶段、可核查的候选差异、仍缺少的证据。全片层保留主线和事件索引。例如“早先站立展示主体；此处出现连续行走”是可查证差异，不直接写成“此处一定更精彩”。

区分采样事实、推断和未知；只保存源帧可支持的内容，不把原 query 当成可见事实。第一次实验不加入五维数值、总分、REZE 排名或人为给定的高光答案。记忆总文本上限拟为 4,096 token，截断/压缩规则也需在运行前冻结。建库成本、压缩损失和来源引用错误单独报告。

### 5.4 输出与评价

所有组一次输出最多 20 个不重复的 2 秒候选 ID、重要性分值及简短依据；允许同分、证据不足和空结果。网格 ID 直接绑定时间，禁止自动扩展为覆盖整片的大区间来提高召回。格式、分值含义、同分排序和不足 K 个的处理对四组一致。

- 主指标：完整 10 视频的 **UMT Top-5 mAP**；首要配对差值为 `D_full+M − D_full`。
- 辅助：Recall@5/10/20、Top-5 正例比例、来源引用有效率、非法/重复时间候选、弃判和同分比例。Recall 按每位标注者的重要性中位数二值化后计算，零正例处理预先固定。
- 候选召回以完整时间轴 GT 为分母；候选集上的 oracle 仅作冻结预测后的离线诊断，不反向挑候选。
- Top-5 AP 可从已给出的前五排序计算，并与当前 UMT 实现核对等价性。不用 REZE 分数补全未输出位置；少于五个有效候选时，主指标按不可用预测记零信用并单列。输出最多 20 个候选不能据此声称得到完整 mAP50 或完整时间评分曲线。
- 所有失败、未运行样本保留在原分母；报告每视频差值及视频级配对 bootstrap 95% 区间（10,000 次，seed=42）。小样本区间跨零表示当前不能排除无收益，不等于已证明两者相同。

首轮只检验可行性。拟将主差值至少 +1 pp 且 Recall@20 不下降作为继续研究的开发信号，同时报告区间；它不是统计显著性或自动扩量许可。若目标是压缩，另预设相对 D_full 的 Top-5 mAP 损失不超过 1 pp、在线 GPU 时间降低至少 20% 的探索性门槛，完整建库成本仍计入。所有门槛须在见新结果前确定。

## 6. 后续的记忆、价值与长视频消融

### 6.1 五维 0–2 分应回答“贡献有多大”

先区分：**证据是否存在、对全片贡献多大、模型多确定**。0 表示观察到但没有明确额外贡献，未知用 `null/insufficient`；不能把看不清记为 0。下表是待讨论的量表，不是已验证的判断标准。

| 价值维度 | 1 分示例 | 2 分示例 | 不应自动给高分 |
|---|---|---|---|
| outcome：结果/进展 | 清楚展示一个中间步骤或局部结果 | 呈现主线关键完成、转折、明显前后变化 | 人物/物体只是出现在画面中 |
| information：信息 | 提供可读、与事件有关的新信息 | 消除理解主线的关键疑问或给出核心解释 | 品牌、背景文字或主题反复出现 |
| emotion：情绪 | 与事件关联的可见反应 | 强烈且归属明确、对事件有意义的反应 | 单纯微笑、仅凭面部表情推断高潮 |
| action：动作 | 可辨认的相关动作阶段 | 关键动作、显著难度或能区分候选的执行差异 | 任何运动、镜头移动或普通走动 |
| sensory：感官呈现 | 清楚呈现有观看价值的细节 | 与事件相关、明显突出的呈现或变化 | 颜色鲜艳、清晰或显眼本身 |

每维输出 `score/null + evidence_ids + comparison_event_ids + missing_evidence`，比较性断言必须有对应候选的证据。允许单个维度支持高光，不能要求五项都成立，也不先把五项简单求和。五维用于解释和区分候选，最终仍判断主线贡献、关键进展及非重复性。

只有基础记忆对照形成可解释结果后，增加一次独立的 `事实记忆 vs 同一事实＋五维证据` 对照。小模型输出只作为观测线索，需先核查情绪强度、动作和显著性误报；加入小模型或 ASR 会改变信息与成本，不能与记忆格式一起更改。

### 6.2 长视频 Agent 与定位扩展

LensWalk-adapted 在上述输出契约稳定后接入，固定相同帧池及上限，日志须区分规划调用、观察调用、重复观察和最终答案。完整 Agent 的收益属于系统效果，不归结为某一个记忆字段。

随后在已有长视频数据中按预先冻结、与 AP 无关的规则选小规模完整子集，研究多 query 复用；报告建库冷启动成本，以及实际 N 个 query 下的摊销成本，不能凭设想的 query 数宣称更便宜。

QV 的扩展维持 grounding 输出，以 R1@0.5/0.7、mIoU、Recall@K（固定 IoU 与区间预算）评价，不用 TVSum 的排序收益代替定位收益。原 QV20 的既有实验不重跑，只有新增条件所需的严格配对控制才另列预算。

## 7. Jev / VideoJev：接口核查与最小验证

### 7.1 两者不能混为一个可替换评分器

若纪要中的 Jev 指 TypeSafe Jev，其公开接口提供 Yes/No 概率，以及依据有序标准输出分值和各等级概率的 Score。这个设计可用于理解 0–2 分；本轮未确认其原生视频输入契约，也未调用该服务。[Score](https://docs.typesafe.ai/primitives/score)、[Noul](https://docs.typesafe.ai/primitives/noul)

VideoJev 是另一套公开视频模型实现。官方发布的 4B / 35B-A3B 使用 Qwen3.5-4B / Qwen3.6-35B-A3B，并训练了候选评分头和语言骨干；不能将其头直接装在现有 Qwen3-VL-8B 上获得同等效果。论文实验中的 QV 是 TimeLens 修订标注的 grounding 评价，不能当作我们的高光 mAP 基线。[论文](https://arxiv.org/abs/2610.18615)、[检查点说明](https://github.com/MCG-NJU/VideoJev/blob/7f8b38aa7df67721303cdc61f06d8435f3c7db89/docs/CHECKPOINTS.md)、[评价说明](https://github.com/MCG-NJU/VideoJev/blob/7f8b38aa7df67721303cdc61f06d8435f3c7db89/docs/EVALUATION.md)

### 7.2 代码实际支持什么

核查提交：`7f8b38aa7df67721303cdc61f06d8435f3c7db89`。

- `predict_video(processor, video, questions, ...)` 支持 `grounding` 和 `choice`；前者对时间候选做 sigmoid，后者对答案选项做 softmax。
- `context` 参数是上下文 token 上限，**不是整片背景文字字段**。当前接口没有独立的“背景＋局部片段＋价值规则”三个输入槽；附加背景需明确拼进 query，属于提示适配。
- 时间分数对应原生两帧一组的时间单元，并非固定 2 秒。必须保存 `score_times`、`score_bounds` 和实际解码时间，再按区间重叠加权投影到评估网格，不能按数组下标硬对齐。
- `max_frames` 会在超限时改为覆盖全片的均匀采样；预处理还会依据 context 自动调整分辨率。配对条件必须冻结最终像素及时间记录，不能只写相同 fps。
- 默认定位阈值 0.25 及连续区间解码属于 grounding。即使全部证据弱，解码仍可返回一个非空区间；这不等于“肯定存在高光”。高光验证先用原始概率排序，不套这个阈值，也不把单一定位区间当完整高光输出。
- `predict_features` 支持复用视觉特征；公开路径是否复用语言 KV 需分别验证，不能直接把视觉缓存宣称为 KV 缓存。

源码依据：[模型与 API](https://github.com/MCG-NJU/VideoJev/blob/7f8b38aa7df67721303cdc61f06d8435f3c7db89/videojev_hf/modeling_videojev.py)、[处理器与格式](https://github.com/MCG-NJU/VideoJev/blob/7f8b38aa7df67721303cdc61f06d8435f3c7db89/videojev_hf/processing_videojev.py)、[采样](https://github.com/MCG-NJU/VideoJev/blob/7f8b38aa7df67721303cdc61f06d8435f3c7db89/videojev_hf/videojev_video.py)、[时间映射及解码](https://github.com/MCG-NJU/VideoJev/blob/7f8b38aa7df67721303cdc61f06d8435f3c7db89/videojev_hf/videojev_temporal.py)。

### 7.3 最小验证分两步

**J0：验证原生接口。** 获得单独运行许可后，先取旧 QV20 清单顺序的前两条，使用原 query 做 grounding，检查时间单位、概率数量、源帧覆盖、区间合法性与显存/时间。只做接口验收，不据两条样本报告性能提升。使用新模型须检查训练数据重叠，未排除前不能标注为 QV zero-shot。

**J1：验证通用高光信号。** J0 通过后，仍用上述完整 TVSum val10。用 VideoJev-4B 做两个条件：`J_plain` 仅给冻结的通用高光任务；`J_background` 在同一任务前加入同一份无 GT 全片背景。两组共享像素、时间候选、评分头、模型、导出、评价，仅背景文本不同。第一轮不加入五维逐项评分、局部新裁剪或新阈值。背景可以从已冻结记忆派生，但生成方式和字节内容必须固定并记账。

主要比较 `J_background − J_plain`，REZE、最新 Qwen 8B 评分作为同视频的外部参考。由于骨干、训练与输入方式不同，与 REZE 的差值不是“评分头单变量收益”。VideoJev 输出先称“grounding 头的高光迁移分数”；是否具有高光概率校准意义，需要独立校准材料，不能在这 10 条上调阈值后自证。

若以后确需“全片背景＋单独局部视频＋规则→标量”，需另做局部输入适配或训练任务头，工作量高于 J1；不能把现有 API 包装成已支持该原生能力。现阶段优先验证无需训练的 J1，再决定是否训练适合高光的头。

四组试验的**建议硬上限**：130 次总尝试、故障额外额度 0、零重试；每请求输入＋输出最多 32,768 token，总计不超过 **4,259,840 token**；拟同时最多 1 张 GPU、1 次 worker 启动、生命周期至多 3,600 秒（含加载与清理）。这些是停止上限，不是已实测耗时，也不代表单卡已通过容量验证。建库由三种记忆条件共享，但各方法的独立总成本仍需计入一次完整建库。

LensWalk 与 VideoJev 的上下文、显存和生命周期尚需入口 CPU 审查后另定，当前没有完整可执行预算。VideoJev 官方 grounding 使用 4 fps / 147,456 token；较小资源配置只能标为资源受限适配。论文的 H200 前向速度不等于本机端到端耗时。[官方评价设置](https://github.com/MCG-NJU/VideoJev/blob/7f8b38aa7df67721303cdc61f06d8435f3c7db89/docs/EVALUATION.md)

预运行交付：无 GT 输入清单与哈希、模型/处理器版本、帧与 PTS 清单、四组提示及输出 schema、记忆与代表帧规则、预算绑定、模拟响应 CPU 契约测试、运行器源码快照。运行后再交付原始响应、来源链、请求/失败账本、冻结预测、完整分母评价和逐视频错误分析。

任一输入哈希不符、上下文超限、OOM、解析错误或预算触顶即停止后续派发，保留失败并不自动重试。建库出错不能偷偷换用旧 REZE 或人工记忆。科学门槛未通过时先解释质量退化来源，不因某个漂亮案例追加模块或样本。

需要讨论的三个决定：**先完成四组记忆试验；以 LensWalk-adapted 作 Agent 对照；VideoJev 从官方 4B 的接口与迁移分数开始，不先训练 Qwen 8B 新头。** 本文未提供可直接启动推理的命令，运行器、最终帧清单、提示全文及授权都尚未冻结。
