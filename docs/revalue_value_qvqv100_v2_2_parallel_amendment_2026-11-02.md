## 调度变更

原调度器以全局顺序账本运行，无法直接多开实例。保持当前批次自然完成，在确认所有所属模型进程退出、无reserved请求的批次边界，暂挂原CPU调度器并复核边界；若已开始下一批则立即恢复并继续等待。确认安全后仅结束原CPU调度器及等待中的CPU收尾器。不给模型worker发送信号，不中断推理、不重跑已完成请求。

原调度器收到SIGTERM会按原代码写出failed/KeyboardInterrupt终态；该历史收据完整保留，并通过独立handoff_stop_receipt明确记录这是用户授权的CPU调度交接，不能当作模型推理失败或原实验已全量完成。

已完成的原始响应、失败、worker收据和账本前缀原样复制至新续接目录。冻结输入、模型、帧像素/PTS、提示、schema、query契约及request_sha256完全不变。剩余批次仍各10次（末批8次），同一候选的Q/QV保留原交替顺序和同卡关系。跨批次执行顺序改变，需披露多卡调度可能带来的运行间非确定性。

新增协调器最多使用8张空闲RTX4090，并在分配时保留UUID，防止尚未加载模型时重复分配同一卡。当前可用卡预计为0–3；4–7有其他任务，不抢占。每次启动前复核无计算进程、显存<512MiB、利用率<5%、PCI/UUID映射。

全局账本通过文件锁保护预留和提交，推理期间不持锁；允许不同批次独立完成，最终按冻结全局位置整理。请求开始前计入全部token预留，提交时重新读取账本，仅更新自身条目。任何重复请求/批次、未决前置调用或输入漂移均拒绝。失败时停止后续分配，保留正在执行的调用结果并等待所有所属进程退出，不自动重试。
