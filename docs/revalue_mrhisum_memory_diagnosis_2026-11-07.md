# Mr.HiSum固定40视频实验：事实记忆、读取与摘要导出诊断

日期：2026-11-07。依据11月6日完成的440次实验，本轮只读旧预测、记忆和来源帧；新增实验模型调用、token、GPU分配、worker、重试均为0。TVSum40扩展继续独立运行，费用不计入本诊断。未修改旧结果，未推送。

## 1. 核心结论

**读取器确实补回了局部事实，但尚未带来稳定精度收益；当前更明确的问题是事实信息的作用有限，以及“五个建议→完整分数→KTS摘要”的传递不直接。** 不能把该负结果归结为价值记忆失效：这一轮Mr.HiSum选片根本没有输入V记忆，也还不是1fps版本。

目前可以确认：

- F-read将旧B0候选的局部事实覆盖从144/200提高到182/200，引用新增事实的选择出现在27/40视频中。不是读取器没有运行。
- F-read相对F的mAP50、mAP15、F1差值均无稳定收益，三个95%配对区间都跨0。
- F-read的190个片段建议中，60个完全不进入最终摘要。摘要选择器对建议的传递是一个实测瓶颈。
- Constant的高摘要F1包含KTS长度及背包选择结构的影响；它是恒定分数，**不是均匀时间采样选片**，也不能据此认定它更理解视频。
- 技术健康度良好：320条建库全合法；120条选择119合法，1条tier顺序无效；440条都正常结束输出，无截断。它不是目前精度问题的主要来源。

## 2. 本轮到底测了什么

固定历史1888条可用视频清单的前40条，视频长度124–293秒；清单在读GT之前按历史确定性规则固定。这是开发诊断子集，非官方2000条全量。

| 条件 | 实际内容 |
|---|---|
| B0 | 缓存的8B REZE完整1秒分数曲线 |
| B0_5s_flat | B0按官方float32取5秒均值，再广播回1秒；纯CPU导出参照 |
| D | 27B直接看旧全局/候选图像，无文字记忆，输出最多5个5秒格建议 |
| F | 相同27B、图像、提示，加入旧轮转读取的事实文本 |
| F-read | 只改F读取内容及可引用事实ID，补候选局部/前后/多样性证据 |
| Constant | 每秒固定0.5，随后使用同一官方摘要选片器 |

D/F/F-read共享77–83张旧帧。建库每视频64张全局帧，分8组；全局相邻观察间隔的视频中位数为3.5秒，最长约5.01秒，时间组跨度中位数约23.96秒。整体相当于约0.305fps，并非TVSum当前的1fps。

建库虽保存了简版价值字段，但核对80条F/F-read实际提示后确认：选片只读F，没有V文本。三组共用五类可选价值说明，尚无详细价值建库或价值读取消融。

## 3. 结果及可解释范围

| 条件 | mAP50 | mAP15 | 摘要F1 |
|---|---:|---:|---:|
| B0 | 58.0026 | 22.1709 | 42.3379 |
| B0_5s_flat | 58.0026 | 22.1709 | 46.2001 |
| D | 59.5961 | 24.4014 | 46.0845 |
| F | 59.4063 | 22.9383 | 47.1429 |
| F-read | 59.0989 | 22.9127 | 45.8208 |
| Constant | 49.2129 | 13.7064 | 56.0692 |

数值均为百分比。主比较F-read−F：mAP50 −0.3074pp，区间[−1.5560, 0.8757]；mAP15 −0.0256pp，区间[−1.8368, 1.4939]；F1 −1.3221pp，区间[−3.9531, 1.2781]。沿用原40视频配对bootstrap，不重算或挑子集。

F-read−D的mAP15为−1.4888pp，区间也跨0；D−B0_5s_flat的mAP15为+2.2306pp，区间同样跨0。D对旧B0还同时改变模型和推理形式，不能归因于单个模块。

**F相对B0的F1增加4.8050pp，其中仅5秒平坦化参照就增加3.8621pp；F相对平坦化参照的点差仅+0.9428pp。** 这不是严格可加的因果分解，但说明不能把前一个差值全部报为记忆收益。D相对该参照的F1反而为−0.1156pp。

## 4. 读取机制：覆盖改善，收益未跟上

| 可审计项目 | F | F-read |
|---|---:|---:|
| 读入事实总数 | 437 | 437 |
| 有局部事实的旧B0候选 / 200 | 144 | 182 |
| 候选的局部/前后证据角色覆盖 | 418 | 542 |
| 明确引用事实的建议 / 190 | 164 | 181 |
| 所有引用事实均在建议片段之外 | 26 | 22 |

完整库共699条事实，现有库最多能覆盖186/200个B0候选，因此新读取器已接近该库的局部覆盖上限。所有读取视图保留完整bank，未重建事实。37/40条F文本发生变化，总共换入66条、换出66条；27视频、42个建议明确引用了新增读入的事实。

但326/437个读入位置属于原时间组/不确定性覆盖底线，约74.6%；可重新分配的位置有限。新旧方法共有371/437条读入事实。30/40视频的完整导出分数确实改变，不能把整体结果接近说成“输出全一样”。

局部覆盖只证明引用时刻在附近，不证明事实正确、动作已完成或值得观看。699事实中690条被旧模型自判clear，只有9条uncertain，这不是人工准确率。22个全片外引用也不自动等于22个语义错误，因为协议允许前后背景；详见逐建议来源表。

**待检验假设：** 当前瓶颈可能更多在事实是否保留了关键动作与相对价值，而非读取不到候选附近的文字。现有诊断支持这个方向，但尚未证明加密采样或加入V一定能改善。

## 5. 五个建议不等于最终摘要

实际链路：模型给最多5个5秒格建议 → 重排原B0分数multiset → 广播回1秒 → 官方KTS段均分 → 15%时长背包 → 摘要F1。

本轮1695个5秒格全部在可选choice域中，未发现候选表遗漏整段网格的问题。但选择器只给少量建议，没有重新判断全视频每段的重要性；其余部分继续依赖原B0顺序。

本次CPU重建了已有6条件×40视频的240个摘要掩码，全部与旧报告的F1、摘要长度、选中秒数一致；没有产生新模型预测或更改评价器。

- F与F-read有18/40个最终摘要完全一致；其中8个视频的分数已改变，但未改变摘要。
- 原报告中有25条F1相同；其中7条其实摘要内容不同，只是重合秒数相同。指标相同不等于预测相同。
- D的185个建议有50个完全落在最终摘要之外；F为54/190，F-read为60/190，即31.6%。
- 官方端点约定使这40视频的预测摘要原长度均为N−1，再按原评价代码补0；所有条件共用，诊断未改动它。不能把这个共同约定未经对照就指认为主要根因。

## 6. 为什么恒定分数的F1这么高

源码中，背包每个KTS段的收益是**该段平均分**，代价是段长度。若所有分数都为0.5，每个段收益相同，优化就倾向在15%时长内装入更多短段，再由固定顺序处理并列。因此它是一种由分段长度和并列规则决定的选择，绝非均匀时间覆盖。

实测所有KTS段平均约4.918秒，中位数4秒；Constant选中段平均仅1.866秒，中位数2秒。F-read选中段平均2.294秒，也受同一结构约束。Constant的F1在28/40视频高于F-read、8条低于、4条相等。

另一个支持性检查：用原GT分数经过同一选片器，38/40条与存储的GT摘要逐秒完全一致；另外两条`video_24642`、`video_11389`各差1秒。**这表明参考摘要与这套选片结构高度一致，但仅凭数值复现不能独立断言标注的完整生成来源，也不等于标注错误。** 两条1秒差异原因本轮未定位。

Constant的mAP15仅13.7064，明显低于F-read的22.9127。F1较高与高光排序较弱可以同时成立。后续主结论应继续看mAP50/mAP15，并把摘要F1及其选片器单独解释。

## 7. 具体案例

审查清单预先固定为原清单前3条，加按原顺序遇到的首个mAP15上升/下降/持平、无效与弃权案例，去重后5视频。未因结果好看挑案例；以下视觉判断仅为助手查看旧缓存图像，非独立人工语义真值。

### 7.1 `video_13034`：记忆补回成品展示，但摘要没有接收

F-read新增读入`g07.f01`，引用240.474/244.478/248.482秒的发型展示。选择器把clip49，即245–250秒，排为第一；248.482秒旧帧确实可见完成的发型与发带。

导出后该5秒格分数为0.837657，但它位于KTS段[238,252]内；该段背包代价14秒，段均分被其他秒拉至0.352684，全片预算37秒。最终该段未被选入，**第一名建议在摘要中保留0秒**。这是可复现的建议与摘要不一致，不证明参考摘要必须包含这段。

同视频D有唯一无效输出：tier为`[0,1,1,1,0]`，最后一项回到0，违反非递减规则。响应finish=stop、230个输出token，无截断；失败已按原协议保留并回退，本诊断未去改它。

### 7.2 `video_9757`：来源变得更贴近，两个指标却不同向

视频包含游戏交易界面和利润总结。F-read新增`g04.f01`，引用86.487/88.489秒利润文字，把85–90秒建议的事实引用换成本地证据；原F引用的是稍后同一利润画面的`g05.f00`。检查的旧帧确实显示“15,367G−7,320G＝8,047G”的总结。

该首选片段并未变化，其他建议改变。F1由9.52升至38.10，但mAP15由14.79略降至14.56。可说明引用更局部、摘要结构改变，不能证明新增利润事实是全部指标变化的原因。也说明片外引用有时是同一内容的延续，不能机械当作幻觉。

### 7.3 `video_6458`：换了背景片段，F1下降

前三个动作建议及第四项保持不变；第五项从10–15秒片头换成0–5秒讲解者/场地画面。mAP15略升约0.26pp，F1从27.50降至20.00。新读入的`g04.f01`是运动后停顿，并未被此次输出明确引用，不能据此认定这条事实导致下降。

### 7.4 `video_23234`：改变排序，未改变摘要

F与F-read建议同样5格，只交换中间两项；最终摘要完全相同，F1均54.17。两者第二位的145–150秒情绪画面均未进入最终摘要。该例说明排序变化不一定穿过后续摘要选择。

### 7.5 `video_26502`：视觉弃权不应混作技术失败

0、37.48、78、118、158.08秒的5个审查位置都是同一紫色logo/宣传画面；D/F/F-read均合法输出空建议，回退到B0_5s_flat。该视频F1为47.83，不是新增模型成功挑出摘要的证据。没有音频输入；尚不能判断时间标注是否来自音频线索，也不能断言整段视频或标注有问题。

## 8. 后续推进建议

1. **保留当前结果为“稀疏事实读取”对照。** 等TVSum40的1fps＋V结果齐备，再决定是否迁移这套记忆到Mr.HiSum；不能把当前Mr.HiSum结果写成相同方案的跨数据集验证。
2. **单独解决建议与评价单元的连接。** 优先设计5秒评分/建议如何影响KTS段的受控对照，保持官方评价和15%预算不变；不要同时改记忆、采样、提示和导出。本轮未执行任何新选片器或模型条件。
3. **再检验事实/价值质量。** 读取覆盖已明显提高，继续微调候选覆盖优先级的优先级下降。密集观察、关键事件记忆和详细V需各自独立对照，允许无收益，不能因为预期有效就扩跑。
4. **mAP与F1分开报告。** 保留B0_5s_flat、Constant及建议保留率；不把Constant称作均匀选片，不把平坦化收益全部归于模型。
