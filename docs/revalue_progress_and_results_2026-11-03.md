# ReVALUE 最新实验进度与结果

> 更新日期：2026-11-03。承接 11 月 2 日汇报，覆盖 10 月 30 日以来的 grounding 基线与 verifier 工作，重点补入 32B 前 20 条结果、事实生成诊断及视频审查页面。旧报告、失败记录、预测与账本均保留。

## 1. 本次组会要讲清楚的结论

**输出格式与引用合法性已经改善，但 verifier 找出错误区间的能力仍不足。32B 已完成前 20 条验证，没有带来改善，反而大量输出“证据不足”。** 当前需要优先查清事实提取、证据支持关系和 unknown 传播的问题，再判断价值提示是否有稳定收益。

研究主线是 **grounding**。当前 verifier 判断固定候选是否满足 query 的内容要求，尚未修改候选边界，也未执行定向补证。因此现有结果是“检错实验”，不能表述成最终定位精度提高。

|---|---|---|

## 2. 当前方法：Direct 定位，verifier 核验内容

1. **REZE Direct**：整视频输入 Qwen3-VL-8B-Instruct，一次生成时间区间列表；固定这些候选作为后续参照。
2. **Query 条件**：助手仅依据 query 拆解必要条件、实体/事件、依赖与逻辑，并预先冻结。尚无独立人工审校。
3. **证据输入**：每个候选使用相同缓存帧及真实 PTS，包含片内和前后文。每臂、每候选一次调用。
4. **事实与检查**：模型输出可见事实及帧 ID，再逐条件给出 supported / contradicted / unknown 和引用。
5. **CPU 检查与汇总**：普通重复引用稳定去重；检查引用、区域、依赖和时间关系；保留 invalid。合法输出按条件逻辑归为支持、报警或证据不足。

Q 与 Q+V 共用条件、候选、帧、schema 和验收规则。**Q+V 额外提供适用价值视角的支持证据、反证限制、缺证标准和禁止推断说明**。五维视图由条件映射生成，不是另外调用模型生成五个价值分数；没有适用维度时两组提示相同。

当前未加入整视频记忆、候选比较、回看、ROI、音频或边界改写。结构合法只能说明输出满足契约，不能证明事实真实、引用足以支持结论。

## 3. 从相关工作到当前价值判断设计

原 v1.1 合法输出的 405 个价值字段中有 361 个 NA，61 条记录五维全 NA；这说明字段使用不足，但没有价值真值，不能将其称为漏检率。后续设计将抽象维度转成“与 query 对应的具体核查问题”。

| 文献及原方法思路 | 借鉴到本项目的做法 | 迁移边界 |
|---|---|---|
| **VisionReward**：将多维视觉偏好拆成具体二值问题，再学习组合权重。[论文 §2](https://arxiv.org/html/2412.21059v2#S2) | 将五类视角写成操作性题库，说明什么支持、什么反证、什么仍然缺证 | 借鉴问题化设计；未接入其权重或奖励模型，也不把生成质量等同于 grounding 正确性 |
| **UnifiedReward-Flex**：按输入内容形成细粒度评价标准。[论文 §3.2](https://arxiv.org/html/2602.02380v1#S3.SS2) | 仅激活 query 需要的价值视角，再实例化对应核查项 | 本项目在看候选结果前冻结条件，不动态增添“必须精彩”等要求，不强制二选一 |
| **DSG**：把文本拆成原子问题及依赖图，约束相互矛盾的回答。[官方项目](https://google.github.io/dsg/) | 保留对象、属性、动作及关系的依赖，检查证据是否绑定到同一对象/事件 | 增加 unknown、帧引用与时间作用域；未使用 DSG 模型，不把父条件缺证当作子条件为假 |
| **VTune / temporal consistency**：对定位出的事件及组成条件做验证，并训练一致性。[论文 §3、§5.3](https://arxiv.org/html/2411.12951v1) | 在 Direct 候选之后核查内容，并单独评估 verifier 是否可信 | 当前没有执行 VTune 训练；模型自洽也不等于真实正确 |

这些是**设计原则的借鉴**。沿用的五类名称来自本项目此前的 ReVALUE 方案，并非直接复制某篇论文的维度体系；当前没有复现或接入上述工作的训练权重。

五类视角的具体含义：

| 视角 | 具体核查 | 防止的跳跃 |
|---|---|---|
| 结果 outcome | query 要求的完成结果或状态变化是否发生 | “射门”不能自动等同“进球” |
| 信息 information | 指定内容、文章或过程能否辨认 | “屏幕有字”不能直接证明“阅读文章” |
| 情绪 emotion | 指定人物是否表现出所要求的反应 | 观众欢呼不能替代球员本人庆祝 |
| 动作 action | 必要动作、接触或先后阶段是否成立 | 拿着工具不能直接证明使用工具 |
| 感官 sensory | 指定外观、颜色、方向属于哪个对象 | 横屏方向不能证明屏幕内容 |

例如 query 要求“男子横持手机阅读文章”：先核查人物—手机关系、横屏、文章内容及阅读行为；若屏幕不可辨，文章条件应保留 unknown。不会为了凑齐五维再要求人物兴奋或画面优美。这个例子解释规则，不是新增实验预测。

完整依据见[相关工作调研](revalue_value_verification_related_work_2026-10-31.md)与[价值判断设计 v2](revalue_value_judgement_design_v2_2026-10-31.md)。本次重新核对四项原始来源；没有复现其性能。

## 4. 8B：完整 100 条的结果没有变化

QVHighlights train 开发清单固定 100 条，139 个候选。与任一 GT 的最大 IoU < 0.5 作为错误代理：85 个代理错误、54 个代理正确。低 IoU 可能来自内容、边界、覆盖或标注差异。

| 指标 | Q | Q+V |
|---|---:|---:|
| 合法 / 无效 | 136 / 3 | 137 / 2 |
| supported / insufficient | 70 / 59 | 63 / 64 |
| 报警 | 7 | 10 |
| 代理正确报警 TP / 误报 FP | 6 / 1 | 8 / 2 |
| 错误召回率 | 7.06% | 9.41% |
| 报警精确率 | 85.71% | 80.00% |
| 代理正确区间误报率 | 1.85% | 3.70% |

Q+V 净增加 2 个正确报警、1 个误报，证据不足增加 5 个；这是计数差，不表示两组报警集合具有包含关系。报警少、缺少独立语义标签，尚不足以证明稳定价值收益。

工程修复方面，同验收口径下旧 v2.2 无效 23 条，新 v2.4 无效 5 条。本轮原始响应严格验收有 52 条无效，普通引用去重恢复 47 条；最终合法率 98.20%。剩余 2 条为长度上限导致 JSON 不完整、3 条为时间顺序缺少足够有序事实。**验收改善不等于语义能力改善。**

原基线完整 100 条 R1@0.5 为 39.00%、R1@0.7 为 30.00%、MR mAP 为 26.48%。本轮未改写定位输出，没有新的最终 grounding 指标提升。来源：[8B 完整结果](revalue_value_qvqv100_v2_4_results_2026-11-02.md)、[Direct 基线](reze_direct_grounding_qv100_results_2026-10-30.md)。

## 6. 新诊断：32B 的问题发生在事实生成阶段

**具体例子：qid 2781，Direct 候选 [37,41) 秒，Q 组。** Query 为 “Guys throw boomerangs at targets inside a gymnasium.” 两模型接收同一批 16 帧和相同任务输入。

- 32B 仅写出 `The required evidence is not available.`，引用片后 f0089（44.744701 秒），三个条件均 unknown。原始响应就如此；前端及引用去重没有删掉具体描述。本条正常 stop，输出 378 token，并未达到 2,048 token 上限。
- 8B 写出人物投掷、黄色烟雾对应击中目标的两条描述，引用片内 f0074（37.237202 秒）、f0079（39.739700 秒）。这些是模型陈述；助手查看旧帧不能独立确认完整动作因果，不能直接当作真值。
- 该 query 的 GT 为 [56,60]、[72,98] 秒，这一 Direct 候选 IoU=0。8B 支持这一候选，也不代表定位正确；仍需视频语义审查。

全部 74 个配对请求中，32B 有 **25 条非空 facts 全部是三种固定套话**，8B 为 0。三种字符串严格限定为 `visible fact`、`The required evidence is not available.`、`The required evidence is not established.`；这是文本模式统计，不是人工事实错误率。

| 证据层级 | 当前可以说什么 |
|---|---|
| 已核验 | 空泛文字来自原始回答；普通去重只减少重复 ID；本例不是截断；完整输入一致 |
| CPU 契约检查已复现 | 当 schema 分支没有片内事实时，后续条件只能 unknown；这解释传播路径，不解释最初为何选择片外事实 |
| 支持性线索 | 提示示例包含占位事实和 unknown 理由，32B 多次复用相近文字 |
| 尚待检验的原因 | 示例文字诱导、强结构约束放大偏差、模型特性或三卡运行配置影响；目前不能选定根因 |

当前验收主要约束 ID、区域和条件关系，无法阻止“证据不可得”这种元判断占据可见事实字段。来源：[事实生成诊断](revalue_32b_fact_generation_diagnosis_2026-11-03.md)。

## 8. 下一步建议：先解释退化，再扩展模块

以下为待讨论的建议，本次没有启动实验。

| 顺序 | 具体工作 | 如何判断是否有效 |
|---|---|---|
| 1 | 利用视频页面，按预先固定规则覆盖支持、报警、证据不足和无效案例，独立审校 query 条件及事实 | 区分内容错误、边界错误、可见性不足和标注疑点，记录审阅分歧 |
| 2 | 固定前 20 条与旧帧，单独改变占位示例文字；另一个独立条件再检查结构约束 | 除合法率外，检查事实是否具体且有来源、正确条件判断和误报；允许负结果，不强迫分差或报警 |
| 3 | 在事实质量可用后复核 Q / Q+V 的额外贡献 | 同候选逐项比较改善和退步，不将更多非 NA、更多描述或更长提示当收益 |
| 4 | 对确认因缺少视觉信息失败的情形，设计等量均匀补帧与定向补证对照；单独设计边界验证 | 比较证据是否真正补足；如修改区间，再评价 R1 / MR mAP |

32B 三卡运行路径仍是未排除因素；若需要对照，应另列运行条件实验，避免与提示或 schema 同时改变。新实验需先冻结变量、范围与验收标准，再取得执行授权。当前不继续扩大 32B 样本、不自动加入回看或边界修正。
