## 1. 本轮做了什么

旧理由被拆为 22 个注册原子，绑定原文 span/hash、主体、属性／动作和时间量词；模型逐项给出关系提案与局部引用。控制器检查同主体、同谓词、实际 PTS、证据类型及有限互斥关系，将缺证与反证分开，另存拒收理由。

模型、原输入帧／PTS、事实记忆 F、五维价值标准、温度／seed 和各阶段 token 上限保持不变。旧 R_keep 直接作冻结对照，未重跑。提示、schema、原子输出和控制器是一个模块修复，不能据此分别估计各部分的因果贡献。

CPU 审查修复了观察未知时原子反证可直接通过、全注册原子支持被误读为整句为真等问题。57 项测试验证代码规则与账本边界；它们没有证明模型正确理解 `state` 或看对画面。

## 3. 具体改善与未通过的原因

### 缺证式反证能被拒收，但模型仍会提出它

WxtbjNsCQ8A，200–202s，模型仍把蜂蜜滴落标为 contradicted，同时明确将证据类型填为 absence：“没有显示滴落”。局部关系规则返回 unknown，最终控制器也不接受该反证。说明代码能挡住这一输入，不能说明模型已经学会正确反证。

其他案例的提案有所改善：Awm 300–302s 不再用“手伸入轮毂”否定“瘪胎／裂口”；iV 18–20s 不再用车间首帧否定随后道路画面；Gs 98–100s 不再用“车落水”直接否定“男孩落水”；笼子 22–24s 返回 unknown，未再用没看到狗作反证。这是固定案例上的变化，不能外推总体精度。

### 全局观察状态过粗，连正向证据也被挡住

16 个候选中，模型将 12 个候选的 `state` 标为 insufficient。其中 10 个同时把 `contribution` 标为 supported，说明它仍把“看清了什么”“旧理由是否完整成立”“是否足够精彩”混用。

车辆案例 z_6gVvQb2d0，270–272s 最明确：原子 a2 提出同一对象是 `emergency_response_truck` 而非 `passenger_bus`，有 f0313／f0081 引用；红色、横幅文字也分别获支持。但它把全局 state 标为 insufficient，给出的缺口却是“除了车辆存在没有突出的事件”。这是价值层面的迟疑，不等于车辆外形不可见。

新代码为了防止“观察未知却接受反证”，对 `state=insufficient` 的候选覆盖了全部原子判断。这条**全局规则过粗，是本轮实现带来的问题**。车辆正向反证和多个局部可见属性因此一起被压成 unknown，未达到正向对照保留门槛。

离线重放同一批已保存的结构字段可直接定位该覆盖：全局覆盖前为 10 supported、1 contradicted、11 unknown；实际为 3 supported、0 contradicted、19 unknown，即 7 个支持和 1 个反证被覆盖。这个 CPU 重放没有改变输出，**不是新模型预测、修复后性能或语义正确率**。

### 类型／时间检查仍然会接受没有视觉依据的动作

GsAD1KT1xo8，132–134s，模型仍写“滑板与栏杆接触”，并给原子 a4 填了 `event_sequence` 和 f0069、f0070。结构上满足不同 PTS 与同主体要求，控制器因而保留 supported。

助手查看旧缓存中的这些局部帧，看到的是蓝衣人物用手撑栏杆、身体翻落，未见支撑“滑板滑杆”的诊断证据。蓝色衣服可作为可见属性；它不能替滑板存在、滑板与栏杆接触提供支持。

这里还出现依赖缺口：a1“skateboarding”因被填为单帧属性而返回 unknown，a4“滑板滑杆”却可独立返回 supported。当前原子之间没有显式依赖检查。仅要求两个 PTS 或让模型填写 event_sequence，不能证明动作确实发生。

gz 172–174s 则保留开关状态变化、轮胎充气及因果关系为 unknown，与旧缓存能确认的有限证据相符。仍不能把“开关有 0 标记”升级为已启动；这里的改善也是局部开发参考。

## 4. 格式健康与语义结论必须分开

8 条均以 `stop` 结束，没有达到 1536 输出 token 上限。仍有字符串槽位问题：笼子案例的原子描述达到新增 96 字符上限，句尾不完整；Gs 98–100s 的 comparison.basis 达到 220 字符上限，出现不自然的“def偏好”尾部。完整 JSON 不保证完整语句。

相对旧 schema，新结构从带资格约束的联合分支改为先收取模型提案、再由控制器判资格；comparison.basis 上限 200→220、comparison.missing 160→140，新增原子描述上限 96。总输出 token 不变，但这些实际格式差异也是解释范围的一部分，不能把变化全部归因于“原子化”。下一版应固定无关槽位并用短字段避免挤占，而不是增加输出额度。

旧 R_keep 的这 8 对中有 1 条 invalid；旧候选 state 的可用分母只有 14，新版为 16。不能把这两个不同分母直接当成同规模准确率对比。

## 5. 下一步只解决已定位的接口问题

当前版本**不扩到剩余 42 对**。先在 CPU 层准备两个局部修复，再单独申请下一轮模型诊断；本轮 8 次已耗尽，未使用的 token／GPU 时间不兑换额外请求。

1. **按原子记录可观察性，取消全局状态跨层覆盖。** 每个原子分别记录可见事实是否建立、关系是否互斥；高光价值是否突出放在贡献判断中。候选摘要由这些局部结果生成，不能因为“未确认骑行”一起否定“道路可见”。这不等于直接删除所有安全检查：局部引用、证据类型、主体与时间仍需满足。
2. **给依赖性动作加明确前提。** “滑板滑杆”必须引用支持滑板存在和接触关系的观察条目；仅有蓝衣或手撑栏杆不够。前提 unknown 时，依赖动作不能独立得到 supported。依赖图可先从原理由文本审校，不把事后期望答案注入输入。
3. **增加整合夹具，保留正向与负向两类。** 同一候选包含“清楚的颜色／物体类别”和“未知动作”的混合例，应保留前者、阻止后者；也要覆盖“前提未知而结果被支持”。本轮全局 gate 的单条测试过于保守，没有覆盖混合证据的实际表现。

即使以上规则通过，视觉事实本身仍需核查。真正不接收 F／旧理由的观察阶段属于后续独立信息流对照，不能混入上述小修复并归为同一变量。
